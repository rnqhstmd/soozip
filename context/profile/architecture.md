# profile 아키텍처

## 화면 구조

```
ProfileView (탭2)
 ├─ StatsSection      모음집 수 · 총 캔버스 · 이번 달 · 최다 모음집 · 연속 기록
 └─ SettingsSection
     ├─ 알림    리마인더 토글·요일/시간, 이어서 작성·추억 소환·월간 결산 토글
     ├─ 보안    Face ID 잠금
     ├─ 데이터  iCloud 상태·용량, 백업 zip 내보내기/가져오기, 캐시 정리
     └─ 정보    폰트 OFL 고지 5종, 오픈소스, 개인정보 처리방침, 문의, 앱 평가, 버전
```

## 통계 정의

| 지표 | 계산 |
|---|---|
| 모음집 수 | `Collection` 전체 개수 |
| 총 캔버스 수 | `Canvas` 전체 개수 (초안은 애초에 DB에 없으므로 필터 불필요) |
| 이번 달 만든 캔버스 | `createdAt`이 이번 달인 `Canvas` 수 |
| 가장 많이 담은 모음집 | 캔버스 수 최다 `Collection`의 이름 + 개수 |
| 연속 기록 | 캔버스를 1장 이상 저장한 날의 연속 일수 (`createdAt`, 기기 로컬 타임존) |

## 로컬 알림 4종

전부 `UNUserNotificationCenter`. 서버 없음.

| 알림 | 트리거 | 기본값 |
|---|---|---|
| 기록 리마인더 | 사용자 지정 요일·시간 | off |
| 이어서 작성 | 초안 24시간 방치 시 1회 | on |
| 추억 소환 | "1년 전 오늘 만든 캔버스" (해당 날짜 캔버스 존재 시) | on |
| 월간 결산 | 매월 말 "이번 달 N장을 모았어요" | on |

**권한 요청 흐름**

```
첫 캔버스 저장 완료
  → 프리프롬프트 (앱이 직접 띄우는 설명)
      ├─ 허용 의향 있음 → 시스템 다이얼로그
      └─ 나중에 → 아무것도 하지 않음 (재요청 기회 보존)
```

온보딩·첫 실행에서는 묻지 않는다. **앱 기능이 알림 허용에 의존하지 않을 것** (심사 4.5.4).

## Face ID 잠금

```
scenePhase == .inactive  → 백그라운드 커버 표시   ★ .background가 아니다
scenePhase == .active    → Face ID 인증 요구
   인증 성공             → 커버 해제
   인증 전               → 커버 유지
```

**★가 핵심이다.** `.background`에서만 덮으면 위로 스와이프해 앱 스위처를 여는 동안 화면이 그대로 노출된다. 그 구간은 아직 `.background`가 아니기 때문이다.

## 첫 실행

온보딩 화면 없음. 캐러셀에 `[+ 새 모음집]` 카드 하나 + 고스트 힌트.

**샘플 모음집 1개(캔버스 2~3장)를 생성한다.** v3에서는 회색 콜렉트북 17권이 화면을 채워 빈 상태가 자연스러웠지만, v4의 첫 화면은 카드 한 장뿐이라 심사자에게 미완성으로 읽힐 위험이 있다(심사 2.1).

샘플은 **일반 `Canvas`로 생성되어 통계와 검색에 그대로 잡힌다.** 별도 플래그를 두면 모든 쿼리에 필터를 달아야 한다. 사용자가 삭제하면 자연히 사라진다.
