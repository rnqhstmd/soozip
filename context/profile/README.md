# profile (내 정보)

통계·설정·알림·보안. 다른 도메인이 만든 데이터를 집계해 보여주고, 앱 전체 동작을 조절한다.

## 배경

v3의 통계는 전부 **지역 수집 진척률**이었다. "물들인 지역 n/230", "완성한 콜렉트북", "12색 사용 분포" — 지역 컨셉이 사라지면서 세 지표 모두 의미를 잃었고, 사용자가 만든 것을 세는 지표로 갈아 끼웠다.

| v3 | v4 |
|---|---|
| 물들인 지역 n/230 | 모음집 수 · 총 캔버스 수 |
| 완성한 콜렉트북 | 가장 많이 담은 모음집 |
| 12색 사용 분포 | 이번 달 만든 캔버스 |
| 연속 기록 | 그대로 |

## 안 하면 어떻게 되는가

**재방문 동기가 사라진다.** v3에서는 "230칸 중 몇 칸을 채웠다"가 강력한 수집 압박이었는데, v4에는 그런 장치가 없다. 통계와 알림 4종이 그 자리를 대신하지만 **동등한 힘은 아니다.** 이건 설계로 완전히 메울 수 없는 문제이며 v4의 남은 리스크 2번으로 기록돼 있다.

**Face ID 잠금이 없으면** 개인 사진이 든 앱을 남에게 잠깐 빌려줄 수 없다. 타깃 사용자를 생각하면 무시할 수 없는 요구다.

## 사용자와 규모

20~30대 여성, 인스타그램 공유층.

## 성공 기준

- 통계 화면이 "얼마나 모았는지"를 **한눈에** 보여준다
- 알림이 성가시지 않으면서 재방문을 유도한다 (기본 on 3종 / off 1종)
- **앱 기능이 알림 허용에 의존하지 않는다** (심사 4.5.4)
- ❓ 알림 허용률 · 재방문율 — 출시 후 실측 필요

## 출시 전 미결 항목

**문의 메일**은 개발 완료 후 **앱 전용 계정을 새로 개설**해 쓴다. 개인 업무 메일(`bonseung@sqisoft.com`)을 앱스토어에 노출하지 않기 위해서다. 지금 만들어도 출시 전까지 쓸 일이 없고 앱 이름·도메인이 바뀌면 다시 파야 하므로 미뤘지만, **제출에는 반드시 필요하므로 출시 준비의 첫 항목**이다. 상세는 [PROJECTS.md](PROJECTS.md).

## 핵심 결정

| 결정 | 근거 |
|---|---|
| 알림 권한 요청은 **첫 캔버스 저장 직후** | 온보딩이나 첫 실행에서 물으면 맥락이 없어 거부율이 높다. 한 번 만들어 본 직후가 가장 설득력 있다 |
| 프리프롬프트 → 시스템 다이얼로그 2단계 | 시스템 다이얼로그는 한 번 거부하면 앱에서 다시 띄울 수 없다. 프리프롬프트로 걸러야 기회를 낭비하지 않는다 |
| 알림 인박스 없음 | 서버가 없어 보낼 것이 로컬 알림 4종뿐이다 |
| **백그라운드 커버는 `scenePhase == .inactive`에서 덮는다** | `.background`에서만 덮으면 **위로 스와이프해 앱 스위처를 여는 동안 화면이 그대로 노출된다.** 그 구간은 아직 `.background`가 아니다 |
| 연속 기록은 **기기 로컬 타임존** 기준 | 여행 중 타임존이 바뀌어도 사용자 체감과 맞다 |
| 샘플 모음집은 **통계에 그대로 잡힌다** | 별도 플래그를 두면 모든 쿼리에 필터를 달아야 한다(canvas 도메인의 초안 분리와 같은 이유). 삭제하면 자연히 사라진다 |
| 다크모드 미지원 (`UIUserInterfaceStyle = Light`) | 흰 캔버스가 전제인 앱이라 다크모드에서 캔버스만 하얗게 뜬다 |
