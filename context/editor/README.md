# editor (에디터)

흰 캔버스 위에 레이어를 놓고 옮기고 키우고 돌리는 곳. **v4에서 앱의 전부이자 최대 기술 리스크.**

## 배경

v3까지 앱의 차별점은 "다녀온 지역을 파스텔 12색으로 물들이고 그 색들이 메시 그라디언트로 섞인다"는 **색 수집 메커닉**이었고, 에디터는 그 메커닉을 받쳐주는 조연이었다. 2026-08-10에 지역 컨셉이 폐기되면서 색 메커닉이 통째로 사라졌고, **에디터가 주연이 됐다.**

그래서 v4에서 에디터에 세 가지가 새로 들어왔다.

1. **`shape` 레이어** — 원·사각·둥근사각·선·별·하트·말풍선·화살표·삼각형 9종
2. **선택 UI** — v3의 "우하단 코너 핸들 하나가 크기와 회전을 겸함"을 폐기하고 PPT식 바운딩 박스 + 다중 핸들로 재설계
3. **스마트 가이드** — 정렬·균등 간격·크기 일치를 감지해 가이드선과 햅틱을 준다

## 안 하면 어떻게 되는가

**에디터 품질이 곧 앱의 경쟁력이다.** Crsel·STIT 같은 기성 꾸미기 앱과 정면 승부하는데, 색 메커닉 같은 우회로가 더는 없다.

특히 **스마트 가이드가 없으면** 사진 여러 장을 격자로 놓는 가장 흔한 사용 패턴에서 눈대중으로는 절대 줄을 맞출 수 없고, 맞지 않으면 결과물이 즉시 조잡해 보인다. 이건 "있으면 좋은 기능"이 아니라 결과물의 품질을 결정하는 축이다.

**크기와 회전이 한 핸들에 묶여 있으면** 둘 중 하나만 바꾸고 싶을 때 반드시 다른 하나가 딸려 움직인다. PPT·Keynote·Canva가 모두 이 둘을 분리해 둔 이유다.

## 사용자와 규모

20~30대 여성, 인스타그램 공유층. 한 캔버스의 레이어는 최대 43개.

## 성공 기준

- 사진 3장을 **가로 일직선 + 균등 간격**으로 놓는 데 진동 피드백만으로 성공한다
- 캔버스 줌 200%에서도 핸들 조작감이 100%와 동일하다
- 드래그 프레임마다 스마트 가이드를 전수 계산해도 **60fps 유지**
- ❓ 첫 캔버스 완성까지 걸리는 시간 — 출시 후 실측 필요

## 핵심 결정

| 결정 | 근거 |
|---|---|
| 레이어 5종이 **선택·이동·핀치·회전·z-order·투명도를 완전히 동일한 경로**로 처리 | 타입별로 다른 것은 렌더러와 속성바뿐. 조작 코드가 하나면 버그도 한 곳에서 고친다 |
| 크기와 회전을 **다른 핸들로 분리** | 겸용 핸들은 둘 중 하나만 바꿀 수 없다 |
| `photo`·`stamp`·`drawing`에 **변 핸들을 주지 않음** | 한 축으로 늘이면 얼굴이 찌그러지는데, 사용자가 실수를 인지하지 못한 채 저장한다 |
| 핸들 **시각 12pt / 히트 44pt** | HIG 최소 터치 타깃. 시각 크기를 44pt로 키우면 캔버스가 핸들로 뒤덮인다 |
| 핸들을 **화면 오버레이**에 그림 | 줌 배율과 무관하게 크기·히트 영역이 일정해야 한다 |
| 스냅 임계를 **화면 좌표 8pt**로 계산 | 논리좌표로 하면 줌 배율에 따라 감각이 달라진다 |
| **회전된 레이어는 정렬·간격 가이드 제외** | 회전체의 바운딩 박스는 실제 형태와 어긋나서, 박스를 맞춰도 눈에는 안 맞아 보인다 |
| 햅틱을 **정렬 light / 균등간격 medium / 크기일치·회전 selection**으로 구분 | 진동만으로 무엇에 맞았는지 알 수 있어야 한다. 균등 간격이 더 찾기 어려우므로 더 세게 |
| 여러 가이드에 동시에 걸려도 **햅틱 1회**, enter 이벤트에만 발화 | 아니면 드래그 내내 진동이 끊이지 않는다 |
| **레이어는 캔버스 밖으로 자유롭게 나가고 경계에서 잘린다** (클램프 아님) | 가장자리에서 잘린 사진, 흘러나가는 도형은 콜라주의 기본 문법이다. 중심을 가두면 이 표현이 통째로 불가능해진다 |
| 단, 중심이 **작업 영역(캔버스 2배) 밖으로는 못 나감** | 그 밖은 줌 아웃으로도 볼 수 없어 영영 잡을 수 없다 |
| 겹침은 **z-order 4종**으로 해결, 레이어 목록 팝업 없음 | 조작 경로가 둘로 갈리면 사용자는 어느 쪽도 확신하지 못한다 |
| **도형은 텍스트를 품지 않음** | 글자를 넣는 방법이 둘이 되면 폰트·크기·색 편집 경로가 이중화된다. 말풍선 안 글자는 텍스트 레이어를 얹어 해결하고, 함께 옮기는 편의는 P1 그룹으로 |
| 폰트는 **OFL 5종만** | OFL은 앱 임베딩을 명시적으로 허용한다. "상업용 무료" 국내 폰트 상당수는 앱 임베딩이 별도 협의 대상이라 사후 권리 문제가 생길 수 있다 |
| 레이어 상한을 **타입별로** | 병목은 익스포트 출력(1080×1920 RGBA ≈ 8MB)이 아니라 디코딩된 비트맵이다 |
| **복제는 +40,+40 오프셋에 놓고 복제본을 선택** | 같은 자리에 겹쳐 놓으면 어느 것이 새것인지 알 수 없다. 같은 색 동그라미 다섯 개를 찍는 것이 이 앱의 전형적 패턴이라 복제 흐름이 매끄러워야 한다 |
| **누끼 제외** (2026-08-10) | 처리 6단계 + 결과 트림/위치 보정 + `cutoutPNG` 필드 + 품질 편차가 딸려온다. **결정적으로 iOS 사진 앱의 「피사체 들어올리기」로 복사→붙여넣기하면 같은 결과가 나오고, 그건 평범한 `photo` 레이어라 핸들·회전이 그대로 동작한다.** 상세는 media 도메인 참조 |
