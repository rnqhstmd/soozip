# editor 용어 사전

| 용어 | 설명 |
|------|------|
| 레이어 5종 | `photo` · `text` · `shape` · `stamp` · `drawing` |
| `shape` | v4 신규 도형 레이어. 9종 × 파스텔 12색 |
| `stamp` | 날짜 도장 레이어 |
| `drawing` | PencilKit 필기를 캔버스 크기 비트맵으로 구운 레이어. 획 재편집 불가 |
| 바운딩 박스 | 선택된 레이어를 감싸는 1.5pt 실선. 레이어와 함께 회전한다 |
| 코너 핸들 | 사각 핸들 4개. 비율 유지 크기 조절. 대각 반대편 코너가 고정점 |
| 변 핸들 | 한 축만 조절하는 핸들. `shape`·`text`에만 제공 |
| 회전 핸들 | 박스 위 28pt에 뜨는 원형 핸들. **뷰포트 상단**(화면 y = 0) 40pt 이내면 아래로 뒤집힌다. v4 §5.7 문면은 "캔버스 상단"이나 줌+팬에서 목적과 갈라져 `EDITOR-4`에서 정정됨(결정 4) |
| 선택 상태 | 지금 조작 대상인 항목. **식별자(`Entry.id`) 기준**이라 z-order 재정렬에도 따라가고, 저장소에서 사라지면 자동으로 "없음"이 된다. 편집 세션 안에서만 살고 layoutJSON에 저장되지 않는다 |
| 기본 크기 | 레이어의 scale 적용 전 크기. **`shape`만 모델이 스스로 안다**(`width`/`height`). `photo`는 픽셀 크기를 안 들고 `text`는 렌더러가 재야 나오므로 넷은 밖에서 주입받는다 |
| 핸들 배치 | 선택된 레이어가 내놓는 조작점 묶음(코너 4 · 변 0~4 · 회전 · 삭제). **화면 좌표계다.** `CanvasSurface`가 바뀌는 순간 통째로 무효라 저장하지 않고 매 프레임 다시 만든다 |
| 히트 우선순위 | 같은 지점에 겹친 핸들 중 누가 잡히는가. **거리는 보지 않는다** — 제스처가 후보를 거르고(`HandleGesture.accepts`), 살아남은 것 중 `orderedHandles`의 순서가 고른다. 그래서 탭이 삭제를 잡는 것은 **순서** 때문이고(탭은 아무것도 거르지 않는다) 드래그가 좌상단을 잡는 것만이 **제스처** 때문이다. 초소형 레이어에서는 최근접 핸들이 지는 일이 실제로 생긴다(`EDITOR-5`) |
| 히트 영역 | 핸들의 실제 터치 판정 범위. 시각 크기(12pt)와 별개로 **화면 좌표축 정렬 44×44pt 정사각형**이다. 원(유클리드 거리)이 아닌 것이 핵심 — 원으로 바꾸면 코너의 대각 여유가 √2배 좁아진다. **줌 50~400% 어디서든 같은 화면 44pt**라, 판정이 `CanvasSurface`를 참조하지 않는 것이 그 근거다(`EDITOR-5`) |
| 후보 목록 | 한 지점에 겹친 핸들 **전부**를 히트 우선순위 순서로 낸 것. **제스처 종류를 몰라도 조회된다** — 손가락이 막 닿은 순간에는 아직 탭인지 드래그인지 모르지만 그때도 눌린 핸들을 하이라이트해야 하기 때문이다. 확정 판정은 이 목록에서 하나를 고른 것이라, 하이라이트된 핸들과 실제로 잡힌 핸들이 어긋날 수 없다 |
| 화면 오버레이 | 핸들을 그리는 레이어. 논리좌표가 아니라 화면 좌표계라 줌과 무관하게 크기가 일정하다 |
| 스마트 가이드 | 정렬·균등 간격·크기 일치를 감지해 가이드선 + 햅틱을 주는 기능 |
| 정렬 가이드 | 캔버스 중심선 또는 다른 레이어의 좌·중·우 / 상·중·하에 맞을 때 |
| 균등 간격 가이드 | 같은 축에 3개 이상 있을 때 간격이 고르게 되는 지점. 이중 화살표로 표시 |
| 크기 일치 가이드 | 리사이즈 중 다른 레이어와 폭 또는 높이가 같아지는 지점 |
| enter 이벤트 | 가이드에 "걸리는 순간"에만 발화하고, 붙어 있는 동안은 재발화하지 않는 방식 |
| fit | 캔버스가 화면에 꽉 차는 배율 = 줌 100% |
| 작업 영역 | 캔버스의 2배 범위. 레이어 중심이 나갈 수 있는 한계이자 캔버스 팬의 한계 |
| 고스트 | 캔버스 밖으로 나간 레이어 부분을 30% 불투명도로 표시한 것. 익스포트에는 나오지 않는다 |
| z-order 4종 | 맨 앞으로 / 앞으로 / 뒤로 / 맨 뒤로 |
| 복제 | 선택 레이어를 +40,+40 오프셋에 복사. 전 타입 지원, 복제본이 선택 상태가 된다 |
| 붙여넣기 | 클립보드 이미지를 얹는 것. `UIPasteControl`로 허용 프롬프트를 피한다 |
| 역회전 행렬 | 회전된 레이어를 드래그·리사이즈할 때 로컬 좌표로 되돌리는 변환 |
| 회전 스냅 | 회전각이 15° 배수에서 3° **미만**이면 그 눈금으로 흡착하는 것. **경계는 이전 상태다 — 정확히 3°면 흡착하지 않는다**(`edgeHideThreshold`·`cornerPushThreshold`와 같은 관례). **판정 본체는 도(degree) 공간**이다 — 라디안에서 거리·임계를 재면 `\|12°−15°\|`가 임계보다 **작아져** 경계가 깨진다(실측). 흡착은 정규화 이전 원본 각도 기준이라 **누적 바퀴 수가 보존된다**(373°→375°, 359°→360°) |
| 축 정렬 판정 | 정렬·간격 가이드의 후보 자격. **가장 가까운 2π 배수까지의 거리**가 허용오차(0.0001 rad) 미만인가를 본다. 한 바퀴 돈 레이어도 축 정렬로 본다 — 이전에는 `abs(rotation)`만 봐서 후보에서 빠졌다(`EDITOR-8`이 수정). ⚠️ `[0,2π)`로 정규화한 뒤 0 근접 비교로 바꾸면 미세 음수 회전(`-0.00005`)이 깨진다. **회전 스냅의 3°와 목적이 다른 별개 규칙**이라 통합하지 않는다 |
| 배타 제스처 | 한 번에 하나만 활성화되도록 묶은 제스처 인식기. 동시에 물리면 레이어가 순간이동한다 |
