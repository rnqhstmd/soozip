# editor 아키텍처

## 레이어 구조

```
EditorView
 ├─ CanvasSurface            논리좌표 1080×H, 흰 배경, 캔버스 사각형으로 클리핑
 │   └─ LayerRenderer ×N     타입별 렌더러 (photo/text/shape/stamp/drawing)
 ├─ GhostLayer               캔버스 밖으로 나간 부분 30% 표시
 ├─ SelectionOverlay         ★ 화면 좌표계 — 바운딩 박스 + 핸들
 ├─ SmartGuideOverlay        ★ 화면 좌표계 — 정렬선 · 간격 화살표
 └─ ToolPanel                도구 7종 + 선택 레이어 속성바
```

**★ 표시된 둘은 논리좌표가 아니라 화면 좌표계에 산다.** 줌 배율이 바뀌어도 핸들 크기와 가이드선 굵기가 일정해야 하기 때문이다.

## 선택 UI

```
        ↻                     ↻  회전 핸들 (원형, 박스 위 28pt)
        │
  ✕ ─── ■ ─────── ■           ■  코너 핸들 (비율 유지 크기 조절)
  │               │           □  변 핸들 (한 축만 — shape·text)
  □               □           ✕  삭제
  │               │
  ■ ─────── ■ ─── ■           ─  바운딩 박스 (레이어와 함께 회전)
```

| 크기 | 핸들 표시 |
|---|---|
| 짧은 변 ≥ 88pt | 전체 표시 |
| 56 ~ 88pt | 변 핸들 숨김 |
| < 56pt | 코너 핸들을 박스 바깥으로 밀어냄 |

- 크기 하한: 짧은 변 논리 40px / 상한: 캔버스 긴 변 ×4
- 회전 핸들은 박스 상단이 캔버스 상단 40pt 이내면 아래로 뒤집는다

## 제스처 우선순위

| 상태 | 한 손가락 드래그 | 두 손가락 핀치·회전 | 두 손가락 드래그 |
|---|---|---|---|
| 선택된 레이어 있음 | 레이어 이동 | **레이어 크기·회전** | 캔버스 팬 |
| 선택 없음 | 캔버스 팬 | **캔버스 줌** | 캔버스 팬 |

- 줌 범위 **50% ~ 400%** (fit = 100%). fit 아래로 내려가는 이유는 캔버스 밖 레이어를 회수하기 위해서다
- 더블탭으로 fit 복귀
- 캔버스 팬은 작업 영역(캔버스 2배)까지. 그 이상은 고무줄로 되돌린다
- 제스처 인식기는 **배타(exclusive)**

## 스마트 가이드

| 종류 | 기준 | 표시 | 햅틱 |
|---|---|---|---|
| 정렬 (드래그) | 캔버스 중심선 / 다른 레이어 좌·중·우, 상·중·하 | 잇는 실선 | `impact(.light)` |
| 균등 간격 (드래그) | 같은 축 3개 이상, 간격 균등 지점 | 이중 화살표 | `impact(.medium)` |
| 크기 일치 (리사이즈) | 다른 레이어와 폭·높이 일치 | 변 강조선 | `selection` |
| 회전 | 15° 단위 (±3° 흡착) | 각도 배지 | `selection` |

- **각도의 단위 규약**: 저장·모델의 회전값(`LayerFrame.rotation`·`LayerTransform.rotation`)은 **라디안**이지만
  회전 스냅의 **판정 본체는 도(degree)**다(`RotationSnap`). 라디안 진입점은 단위만 옮기는 어댑터다.
  ⚠️ **도 API에 라디안을 넣으면 컴파일되지만 조용히 파괴적이다** — `|r| < 3 rad`(약 ±171.9°) 전 구간이
  `0°`로 붕괴하는데 반환이 유한하고 흡착 성공으로 보인다. 컴파일러가 막지 않으므로 인자 라벨이 유일한 방어다
- 임계: **화면 좌표 8pt**
- **회전값 0°인 레이어만 후보.** 회전체 바운딩 박스는 실제 형태와 어긋난다
- 화면 밖으로 완전히 벗어난 레이어는 후보에서 제외
- 동시 다중 히트 시 햅틱 1회, enter 이벤트에만 발화
- 최대 43개 레이어라 프레임마다 전수 비교해도 부담 없음

## 캔버스 경계

| 구분 | 동작 | 소유 |
|---|---|---|
| 에디터 | 캔버스 안은 정상 렌더, 밖으로 나간 부분은 30% 고스트 | **판정** `EDITOR-9` · **렌더** `EDITOR-11` |
| 경계 | 캔버스 사각형으로 클리핑. 데이터는 버리지 않는다 | `EDITOR-11` |
| 익스포트 | 캔버스 영역만. 고스트 제외 | `MEDIA-3` |
| 회수 | 줌 아웃(50%) 또는 캔버스 팬으로 작업 영역까지 보고 잡는다 | `EDITOR-1` |
| 한계 | 레이어 중심은 작업 영역 밖으로 못 나간다 | **`EDITOR-9`** |

**판정과 렌더가 갈린다.** `EDITOR-9`가 내는 것은 `LayerFrame.overlap(canvas:)`의 **겹침 3분류**와 `CanvasSurface.clampedLayerCenter(_:)`의 **중심 클램프**뿐이다. **30%는 불투명도이지 판정 임계가 아니다** — 면적 비율 임계는 v4 어디에도 없다. 실제 클리핑·고스트 드로잉과 겹침 영역(클립 경로) 계산은 렌더러 몫이다.

**회전 레이어를 배제하지 않는다.** 스마트 가이드는 회전체를 후보에서 통째로 빼지만(축 정렬 박스가 실제 형태와 어긋나서), 경계 판정은 그럴 수 없다 — 회전된 사진도 밖으로 나가고 고스트가 필요하다. 그래서 SAT 4축으로 실제 형태를 본다.

⚠️ **`partial`은 양의 넓이를 함의하지 않는다.** 한 점 접촉과 부동소수 오차(캔버스와 같은 크기 레이어의 90°·180°·270°·360° 회전)가 모두 `partial`이다. **렌더 패스 트리거나 사용자 신호로 쓰면 안 된다** — 캔버스를 꽉 채운 배경 사진이 180°에서 매 프레임 빈 고스트 패스를 열게 된다.

⚠️ **중심 클램프는 타입이 호출을 강제하지 않는다.** 중심을 바꾸는 모든 경로(이동·리사이즈로 인한 중심 이동·회전·생성·복제)가 `clampedLayerCenter`를 거쳐야 하는데, 안 거치면 레이어가 영영 잡을 수 없는 곳으로 나간다. **`EDITOR-10` 착수 전에 구조적 게이트를 세울 것.**

## z-order

맨 앞으로 / 앞으로 / 뒤로 / 맨 뒤로 — **속성바에 상시 노출.** 겹침 조정은 콜라주 편집 중 가장 자주 하는 조작이라 하위 메뉴에 숨기지 않는다.

- 같은 지점 탭 시 z 최상단 선택. 아래 것은 위 레이어를 뒤로 보내 잡는다
- 재정렬 시 z를 0부터 촘촘히 다시 매긴다 (빈 번호가 쌓이면 상한에 부딪힌다)

## 복제와 붙여넣기

**복제** — 선택 레이어 속성바의 [복제]. 전 타입 지원.
- 원본에서 **논리좌표 +40, +40** 오프셋에 생성하고 **복제본이 선택 상태**가 된다 (같은 자리에 겹치면 어느 것이 새것인지 알 수 없다)
- 모든 속성 승계, z는 원본 바로 위
- `photo`는 `assetId`를 공유하되 `filter`·`opacity`는 독립

**붙여넣기** — 사진 도구의 [붙여넣기]. `UIPasteControl` 사용(허용 프롬프트 회피). 클립보드에 이미지가 있을 때만 활성화.

## 레이어 상한

| 대상 | 상한 | 근거 |
|---|---|---|
| `photo` | 8 | 2000px 사진 디코딩 시 약 16MB. 복제본은 `assetId`를 공유해 메모리가 늘지 않지만 개수에는 포함 |
| `drawing` | 5 | PencilKit을 캔버스 크기 비트맵으로 굽는다 |

## 화면 방향

| | 세로 | 가로 |
|---|---|---|
| 상단 바 | 뒤로·제목·완료 | 좌측 세로 스트립 |
| 도구 패널 | 하단 가로 스트립 | 우측 세로 스트립 |
| 캔버스 | 폭 기준 fit | 높이 기준 fit |

**회전해도 레이어 논리좌표는 불변.** 선택 상태·팬 오프셋은 유지하되 줌 배율만 새 fit 기준으로 재계산한다.
