# collection (모음집)

사용자가 직접 만들고 이름 짓는 수집 단위. 캔버스를 담는 그릇이자 앱의 첫 화면.

## 배경

v3까지 이 자리에는 **행정구역 3계층(시·도 17 → 시·군·구 230 → 캔버스)** 이 있었다. 앱이 카테고리를 미리 정해 주고 사용자는 그 칸을 채우는 구조였다. 2026-08-10에 여행·지역 컨셉을 걷어내면서 이 계층 전체가 폐기됐고, **사용자가 만드는 모음집**이 그 자리를 대신한다.

바뀐 것의 본질은 "앱이 정한 카테고리 → 사용자가 정한 카테고리"다. 그래서 v3에서 앱 번들 상수였던 상위 2계층이, v4에서는 사용자가 생성·수정·삭제하는 엔티티가 됐다.

## 안 하면 어떻게 되는가

모으는 축이 없으면 앱 이름 「soozip」이 성립하지 않고, 남는 것은 캔버스 편집기 하나다. 이 경우 Crsel·STIT 같은 기성 꾸미기 앱과 **기능적으로 구분되지 않는다.** 모음집은 v4에서 남은 두 개의 차별점 중 하나다(다른 하나는 에디터 품질).

## 사용자와 규모

20~30대 여성, 인스타그램 공유층. 출시 초기 수백~수천 MAU 가정.

한 사용자가 만드는 모음집은 **10~30개** 규모로 예상한다. 이 추정이 첫 화면을 가로 캐러셀로 두면서도 「전체 보기」 그리드를 함께 둔 근거다 — 20개를 넘어가면 캐러셀 한 줄로는 끝까지 밀어야 한다.

## 성공 기준

- 첫 실행에서 모음집 생성까지 **탭 2회**(캐러셀 [+] → 이름 입력 → 완료)
- 모음집이 30개일 때도 원하는 것을 3초 안에 찾을 수 있다 (캐러셀 + 전체 보기 + 검색)
- ❓ 사용자당 평균 모음집 수 — 출시 후 실측 필요

## 핵심 결정

| 결정 | 근거 |
|---|---|
| 첫 화면은 **가로 캐러셀**, 맨 좌측에 [+] 고정 | 사용자 지정. 만들기 진입점이 항상 같은 자리에 있다 |
| 정렬은 **생성 순서**가 기본, 길게 눌러 재배치 | 최근순으로 자동 정렬하면 카드 위치가 계속 바뀌어 근육 기억이 생기지 않는다 |
| 표지 = **대표 캔버스 썸네일** | v3의 색 혼합 메시 그라디언트를 폐기하고 얻은 결과. 사진이 그대로 표지가 되어 안에 뭐가 들었는지 보인다 |
| `coverCanvasID`가 비면 **가장 최근 캔버스**로 폴백 | 대표를 지정하지 않아도, 지정한 캔버스가 삭제돼도 표지가 비지 않는다 |
| 이름 **중복 허용** | 사용자가 같은 이름을 원할 수 있다. 유일성을 강제할 도메인적 이유가 없다 |
| 캔버스는 **정확히 하나**의 모음집에 속함 | 다대다는 표지·통계·삭제 규칙이 전부 복잡해진다. P2로 미룸 |
