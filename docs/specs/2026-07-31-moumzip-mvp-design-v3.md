## 1. 앱 개요

- **앱 이름:** 모음 집 (Moeum Zip)
- **컨셉:** 다녀온 지역을 **색으로 물들여 모으는 디지털 콜렉트북**. 책장에 시·도별 콜렉트북이 꽂혀 있고, 각 권을 펼치면 시·군·구가 색으로 채워진다.
- **플랫폼:** iOS 17+ (빌드는 Xcode 26 / iOS 26 SDK), SwiftUI, SwiftData + CloudKit. **서버·계정 없음**
- **UX 원칙**
  1. **책장이 목차다** — 첫 화면이 곧 수집 현황이다
  2. **색이 언어다** — 표지·타일·캔버스 배경이 전부 같은 색 규칙으로 그려진다
  3. **만들기는 어디서든 한 번에** — 첫 화면의 [+]에서 3탭이면 에디터에 도착한다
  4. **강제하지 않는다** — 색은 라벨이고 제안일 뿐, 사진과 꾸미기는 자유다

### 차별점의 소재

2026-07-31 경쟁 조사 결과 시장이 두 갈래로 갈려 있다. 지역·지도 앱(포토로그 — 평가 3,100여 개이나 2021년 이후 업데이트 중단 / 마이코리아맵)은 **채우기만 하고 꾸밈이 없고**, 꾸미기 앱(Crsel·STIT)은 **꾸며지지만 모이지 않는다.** 둘을 겸하는 것은 트래버리 정도이며 에디터 수준은 미확인이다. 모음 집은 그 교집합을 노린다. 에디터 완성도로는 Crsel·STIT과 경쟁할 수 없으므로, **차별점은 색 수집·혼합 메커닉 하나에 싣는다.**

## 2. 정보 구조

### 2.1 도메인 3계층

```
콜렉트북 (시·도)        17개      앱 내장 · 생성/삭제/이름변경 불가 · 순서만 사용자 편집
   └ 지역 (시·군·구)    약 230개   앱 내장 · 고정
        └ 캔버스        N개       사용자가 만드는 유일한 객체
```

사용자가 생성·삭제하는 대상은 **캔버스뿐**이다. 콜렉트북과 지역은 행정구역이므로 앱에 전부 들어 있고 비어 있을 뿐이다. 따라서 "콜렉트북 이름 수정 불가"가 구조적으로 성립한다. 사용자 소유의 배치 정보는 **책장 순서(`ShelfPreference`)** 하나뿐이다.

### 2.2 화면 트리

최상위는 **2탭 — 「책장」과 「내 정보」**다. 앱을 열면 책장 탭이 뜬다.

```
탭1 「책장」 (앱 첫 화면)
 ├─ 콜렉트북 17권 · 3열 그리드 · 표지 정면 · 나무 선반
 │   · 표지색 = 그 시·도 아래 모든 캔버스의 혼합 메시색
 │   · 표지 우측 얇은 책배 + 하단 n / m
 │   · 미수집은 회색 점선 표지
 ├─ 길게 누르기 → 순서 편집 모드 (드래그 재배치)
 ├─ 통합 검색 (지역명 + 캔버스 제목)
 └─ 플로팅 [+] → 생성 마법사

콜렉트북 (시·도 펼침)
 ├─ 하위 시·군·구 타일 그리드 (각 타일 = 그 지역 메시색 + 이름 + 캔버스 수)
 ├─ 미방문 지역은 회색 타일로 함께 노출 (수집 압박 유지)
 └─ 플로팅 [+] → 생성 마법사 (① 시·도 채워진 상태로 시작)

지역 (시·군·구)
 ├─ 캔버스 목록 (최신순 / 오래된순)
 └─ 플로팅 [+] → 생성 마법사 (①② 채워진 상태 = 색감만 고르면 끝)

캔버스 뷰어 (전체화면)
 └─ 좌우 스와이프 · 공유 · 재편집 · 메타 수정 · 삭제

탭2 「내 정보」
 ├─ 통계  총 캔버스 · 물들인 지역 · 완성한 콜렉트북 · 12색 사용 분포 · 연속 기록
 └─ 설정  알림 / Face ID / iCloud 상태 / 백업 zip / 캐시 정리 / 정보·라이선스
```

**v2의 별도 '도감'은 폐지한다.** 책장 자체가 도감이므로 완전한 중복이다. 그 자리에 12색 사용 분포 통계가 들어간다.

### 2.3 예외 처리 (행정구역)

- **세종특별자치시** — 하위 시·군·구가 없다. 콜렉트북 안에 지역 1개(`세종특별자치시`)만 두어 3계층 구조를 깨지 않는다.
- **강원·전북·제주** — 특별자치도로 개편된 명칭을 반영한다. 번들 CSV는 행정표준코드관리시스템 최신본 기준이며, 개편 시 앱 업데이트로 교체한다. 사용자 데이터는 **코드**로 물려 있어 이름이 바뀌어도 깨지지 않는다.

## 3. 색 시스템

### 3.1 파스텔 12색 (앱 상수)

명도·채도를 고정하고 색상만 30° 등간격으로 나눈다. 무엇을 섞어도 파스텔을 벗어나지 않는다.

| idx | 이름 | HSL | idx | 이름 | HSL |
|---|---|---|---|---|---|
| 0 | 로즈 | `hsl(0, 55%, 82%)` | 6 | 아쿠아 | `hsl(180, 55%, 82%)` |
| 1 | 피치 | `hsl(30, 55%, 82%)` | 7 | 스카이 | `hsl(210, 55%, 82%)` |
| 2 | 버터 | `hsl(60, 55%, 82%)` | 8 | 블루 | `hsl(240, 55%, 82%)` |
| 3 | 라임 | `hsl(90, 55%, 82%)` | 9 | 라벤더 | `hsl(270, 55%, 82%)` |
| 4 | 세이지 | `hsl(120, 55%, 82%)` | 10 | 모브 | `hsl(300, 55%, 82%)` |
| 5 | 민트 | `hsl(150, 55%, 82%)` | 11 | 체리 | `hsl(330, 55%, 82%)` |

캔버스는 **`colorIndex: 0~11` 정수 하나**만 저장한다. 색 값은 앱 상수이므로 톤을 조정하면 기존 데이터까지 새 톤으로 다시 칠해진다.

### 3.2 지역 색 = 메시 그라디언트 (파생값, 저장하지 않음)

평균 단색으로 뭉개지 않고 **쓰인 색들이 각자 자리에서 번지게** 한다. 그래야 "여기 민트와 라벤더를 썼구나"가 표지만 보고 읽힌다.

```
입력: 그 지역(또는 시·도)에 속한 캔버스들의 colorIndex 배열

1. 색별 개수 집계 → weight_i = count_i / total
2. 비중 상위 6색만 남기고, 잘린 색은 버리지 않고
   색상환에서 가장 가까운 생존색의 weight에 흡수시킨다
3. seed = hash(regionCode)
4. 색마다 배치를 결정론적으로 계산 (개수와 무관):
       rng    = seededRandom(seed XOR (colorIndex × 2654435761))
       각도    = rng.next() × 360°
       거리    = 0.28 + rng.next() × 0.22        // 중심 기준 정규화 거리
       중심    = (0.5 + 거리·cos(각도), 0.5 + 거리·sin(각도))
       번짐    = 0.55 + weight_i × 0.75
       진하기  = 0.55 + weight_i × 0.45
5. 렌더 = 오프화이트(#FCFBF9) 위에 색별 RadialGradient를 겹치고 blur(12)
```

**성질 1 — 위치는 `(지역코드, 색인덱스)`로만 결정된다.** 캔버스를 몇 장 추가하든 기존 색의 좌표가 움직이지 않는다. 민트를 한 장 더 얹으면 **민트 자리는 그대로 있고 더 짙어지기만** 한다. 열 때마다 표지가 달라 보이는 사고가 원천적으로 없고, 성장이 눈에 보인다.

**성질 2 — 상위 6색 제한.** 12겹을 쌓으면 렌더 비용도 문제지만 결국 회색빛으로 뭉개져 메시를 택한 의미가 사라진다.

**작은 UI에서도 같은 규칙을 쓰되 레이어 수만 줄인다.** 렌더 영역의 **짧은 변이 20pt 이하**이면 상위 2색 선형 그라디언트로 축약한다. 별도 규칙이 아니라 같은 데이터의 저해상도 표현이다.

**캔버스 0장인 지역·콜렉트북**은 회색 `#E9E4DA` 플랫이다.

### 3.3 적용 지점

콜렉트북 표지(하위 전체 집계) · 지역 타일 · 캔버스 배경 기본값 · 통계 화면.

계산은 조회 시점에 수행한다. 지역당 캔버스가 수십 장 수준이라 부담이 없다. 책장 17권 표지만 메모리 캐시를 둔다.

### 3.4 구현 메모

SwiftUI 전용 `MeshGradient`는 iOS 18부터이므로 쓰지 않는다. **`RadialGradient` 다중 레이어 + `blur`** 로 동일한 결과를 만들고, 성능은 `.drawingGroup()`(Metal 오프스크린)으로 확보한다 — 실측은 스파이크 S1.

## 4. 캔버스 생성 플로우

[+]는 **책장(앱 첫 화면)에 상시 노출**된다. 콜렉트북과 지역을 거쳐 들어갈 필요가 없다.

```
[+] → ① 어느 시·도에 다녀오셨나요?    17개 · 책장 순서 그대로 · 검색 가능
    → ② 어느 시·군·구인가요?          그 시·도 하위만 · 행정 순서 · 검색 가능
    → ③ 어떤 색감으로 남길까요?        12색 중 하나
    →   에디터 진입 (배경에 그 색감이 이미 입혀진 상태)
    →   [완료] → 저장 시트: 제목 · 날짜
    →   저장 완료 → (첫 저장 직후 1회) 알림 프리프롬프트 → 시스템 권한 다이얼로그
    →   책장 복귀
```

- 각 스텝은 **선택 즉시 다음으로 전환**된다. 상단에 `서울특별시 › 성동구 › 민트` 브레드크럼이 쌓이고, 아무 항목이나 눌러 되돌아갈 수 있다.
- **지역 화면의 [+]는 지름길**이다. 같은 마법사인데 ①②가 채워진 채로 시작해 색감만 고르면 된다. 콜렉트북 화면의 [+]는 ①만 채워진 상태로 시작한다.
- **사진은 에디터 안에서 넣는다.** 다만 v2가 "사진 우선"을 택했던 이유인 **백지 공포**를 막기 위해, 에디터가 열리면서 **PHPicker가 자동으로 1회 제시**된다. 취소하면 그대로 빈 캔버스로 시작한다.
- **저장 시트는 제목·날짜만 받는다.** 지역과 색감이 앞에서 확정되었으므로 v2에 있던 "구 확정" 단계가 사라진다.
- 마법사 도중 이탈은 임시저장하지 않는다 (에디터 진입 전이므로 잃을 것이 없다).

## 5. 에디터

v2 스펙을 그대로 승계하고, 이번에 정한 것과 경쟁 앱에서 차용할 것을 얹는다.

### 5.1 v2에서 승계 (변경 없음)

- **캔버스:** 논리 좌표 1080×1920 고정 (기기 무관 동일 재현, 익스포트 = 스케일 1.0)
- **레이어 4종 통일 구조** (렌더러만 타입별, 선택·변형·z-order 공유): `photo` / `text` / `stamp` / `drawing`(PencilKit을 이미지로 베이크)
- **조작:** 단일 선택. 탭 선택 / 빈 곳 해제. 선택 레이어만 이동·핀치·회전, 우하단 코너 핸들(크기+회전), 선택 시 삭제·앞으로·뒤로. **회전 레이어 드래그엔 역회전 행렬 필수**
- **Undo:** 펜 모드 내 undo/redo · 레이어 삭제 시 스낵바 "실행 취소" · 뒤로가기 시 변경 파기 확인
- **자동 임시저장:** 변경 1.5초 디바운스 → `layoutJSON` 갱신. 재실행 시 "이어서 할까요?"
- **햅틱:** 도장 찍기, 레이어 스냅, 저장 완료
- **재편집(P0):** 뷰어 → 편집 → 같은 에디터에 `layoutJSON` 로드 → 저장 시 `renderedPNG` 재생성

### 5.2 P0 신규

| 기능 | 근거 | 구현 |
|---|---|---|
| 레이어 **투명도** 슬라이더 | 레퍼런스의 투명 속지 질감 | `layoutJSON.opacity`, 렌더러 한 줄 |
| **톤 필터 12종** + 강도 0~100% | 색감을 강제하지 않되 도구로는 제공 | Core Image 색조 매핑, 12색 대응 프리셋 |
| 배경 **색감 틴트** | 선택한 색감이 캔버스에 실제로 보이게 | 종이 텍스처 위 곱하기 합성 |
| **누끼**(배경 제거) | Crsel·STIT 양쪽의 시그니처 기능 | Vision `VNGenerateForegroundInstanceMaskRequest` — iOS 17 온디바이스, 서버·과금 없음. 아래 5.3 처리 규칙 참조 |

**누끼를 P0에 두는 근거:** 사각형 사진만 붙이면 콜라주가 아니라 격자가 된다. 오려붙인 형태가 있어야 스크랩북 감각이 성립한다. API 호출 몇 줄로 되므로 비용 대비 효과가 P0 후보 중 가장 크다.

**누끼의 한계:** 인물·음식·또렷한 사물은 잘 분리되지만 머리카락 가장자리, 유리·투명체, 배경과 색이 유사한 피사체는 거칠게 잘린다. **수동 지우개·복원 브러시(Crsel 방식)는 P1.**

### 5.3 누끼 처리 규칙

온디바이스 추론이라 즉시 끝나지 않는다. 구형 기기에서는 수 초가 걸릴 수 있고, 그동안 아무 반응이 없으면 사용자는 앱이 멈춘 것으로 받아들인다.

1. **사전 지원 확인** — 요청을 만들어 지원 여부를 먼저 확인하고, 지원하지 않는 기기에서는 **도구 자체를 비활성화**한다. 매번 눌러서 실패 토스트를 보게 만들지 않는다.
2. **비동기 처리** — 메인 스레드를 막지 않는다.
3. **로딩 인디케이터** — 해당 레이어 위에 진행 표시를 띄우고, 그동안 다른 레이어 조작은 계속 가능하다.
4. **취소 가능** — 진행 중 취소하면 원본이 그대로 남는다.
5. **타임아웃 10초** — 초과하면 취소하고 실패로 처리한다.
6. **실패 시** 원본을 유지하고 "배경을 찾지 못했어요" 토스트를 띄운다. `cutout` 플래그는 `false`로 되돌린다.

### 5.4 에디터 제약

무제한 편집을 허용하면 메모리와 익스포트가 함께 무너진다. 다만 **병목은 익스포트 출력이 아니다** — 1080×1920 RGBA는 약 8MB에 불과하다. 실제 압박은 **디코딩된 비트맵**이며, 그래서 상한은 전체 개수가 아니라 **타입별**로 건다.

| 대상 | 상한 | 근거 |
|---|---|---|
| `photo` 레이어 | **8개** | v2에서 확정된 PHPicker 선택 상한과 동일. 2000px 사진 한 장이 디코딩되면 약 16MB이고, 누끼를 뜨면 `cutoutPNG`까지 두 배가 된다 |
| `drawing` 레이어 | **5개** | PencilKit을 캔버스 크기 비트맵으로 굽기 때문에 한 장이 사진과 맞먹는다. 여기가 진짜 무방비 지점이었다 |
| `text` + `stamp` 레이어 합 | **30개** | 메모리보다 조작성 문제. 이 이상은 단일 선택 UI로 다루기 어렵다 |

상한 도달 시 해당 도구를 비활성화하고 "사진은 8장까지 넣을 수 있어요" 형태로 안내한다. 익스포트는 `autoreleasepool`로 감싸 피크 메모리를 낮춘다.

### 5.5 빈 캔버스

**사진이 하나도 없어도 저장된다.** 색감만 고르고 아무것도 얹지 않은 캔버스는 UX 원칙 4번(강제하지 않는다)에 부합하며, "그 지역에 색을 남겼다"는 이 앱의 최소 단위로서도 유효하다. 따라서 다음이 성립해야 한다.

- 배경 틴트만 있는 `renderedPNG`가 정상 생성된다 (레이어 0개도 유효한 입력)
- 지역 화면 목록과 썸네일에서 색 배경만으로 렌더된다
- **제목이 비어 있으면 목록에 `색이름 · 날짜` 형식으로 표시한다** (예: `민트 · 7월 31일`). 저장 자체는 제목 없이도 가능하다
- 통합 검색에서 무제목 캔버스는 색 이름으로도 걸린다

### 5.6 도구 패널 6종

사진 · 텍스트 · 날짜 도장 · 펜 · 배경 · **필터**

### 5.7 명시적 제외

캐러셀 분할(Crsel의 핵심이나 인스타 발행용이라 목적이 다름) · 영상 · AI 이미지 생성 · 워터마크.

## 6. 데이터 모델

콜렉트북 17개와 지역 약 230개는 **앱 번들 상수 테이블**이므로 DB에 넣지 않는다. 사용자 데이터가 없는 행을 저장할 이유가 없고, 행정구역 개편 시 CSV 교체만으로 끝난다.

```swift
@Model final class Canvas {
    var id: UUID = UUID()
    var regionCode: String = ""        // 10자리, 시·군·구는 앞5 + "00000"
    var provinceCode: String = ""      // 2자리, 비정규화
    var colorIndex: Int = 0            // 0~11
    var title: String = ""
    var createdAt: Date = Date()       // 사용자가 지정하는 기록 날짜
    var updatedAt: Date = Date()
    var layoutJSON: Data = Data()
    var photos: [CanvasPhoto]? = []
    @Attribute(.externalStorage) var renderedPNG: Data?   // 캐시, 재편집 시 재생성
}

@Model final class CanvasPhoto {
    var id: UUID = UUID()
    @Attribute(.externalStorage) var data: Data = Data()  // 원본 2000px 사본 → CKAsset
    @Attribute(.externalStorage) var cutoutPNG: Data?     // 누끼 결과 (원본 보존 · 되돌리기 가능)
    var canvas: Canvas?
}

@Model final class ShelfPreference {
    var id: UUID = UUID()
    var orderJoined: String = ""       // "11,26,27,…" 17개 시·도 코드
}
```

### 6.1 설계 판단 세 가지

- **`provinceCode` 중복 저장** — 책장 표지는 그 시·도 아래 모든 캔버스를 집계해야 하는데, `regionCode` 앞 2자리를 잘라 비교하는 것은 SwiftData `#Predicate`에서 안전하게 표현되지 않는다. 2바이트 중복이 쿼리 안정성과 맞바꿀 만하다.
- **책장 순서를 배열이 아닌 문자열로** — SwiftData + CloudKit에서 배열 속성은 스키마 제약에 걸릴 여지가 있다. 첫 심사 이후 additive-only로 묶이는 스키마에서 위험을 질 이유가 없다.
- **누끼 결과를 별도 필드로** — 원본을 유지해야 누끼를 껐다 켤 수 있고, 열 때마다 Vision을 다시 돌리지 않아 빠르다. optional이라 CloudKit 제약에 걸리지 않는다.

### 6.2 CloudKit 제약 (v2와 동일)

전 속성 기본값 또는 optional · `@Attribute(.unique)` 불가 · 관계는 양방향 optional · **첫 심사 전 스키마 동결 후 additive-only** · iCloud 미로그인/용량 초과 시 로컬 모드 자동 격하 + 설정에 상태 배너.

### 6.3 레이어 JSON (v1 — 코드가 없으므로 새로 정의)

```json
{
  "v": 1,
  "canvas": { "w": 1080, "h": 1920 },
  "background": { "preset": "kraft", "tintIndex": 5, "tintOpacity": 0.35 },
  "layers": [
    { "type": "photo", "assetId": "…", "x": 540, "y": 700, "scale": 1.2, "rotation": -0.08,
      "opacity": 1.0, "cutout": false, "filter": { "colorIndex": 5, "amount": 0.4 }, "z": 0 },
    { "type": "text", "string": "…", "font": "serif", "size": 42, "color": "#3A3A3A",
      "opacity": 1.0, "x": 0, "y": 0, "rotation": 0, "z": 1 },
    { "type": "stamp", "date": "2026-07-31", "style": "round", "x": 0, "y": 0, "rotation": 0.05, "z": 2 },
    { "type": "drawing", "assetId": "…", "x": 0, "y": 0, "scale": 1, "rotation": 0, "z": 3 }
  ]
}
```

v2 스키마 대비 늘어난 것은 `opacity` · `cutout` · `filter` · `background.tint` 넷이며 **전부 `layoutJSON` 내부**다. CloudKit 스키마는 건드리지 않는다 — v2가 "레이어를 한 덩어리로 묶는다"고 확정해둔 것이 여기서 값을 한다.

## 7. 지역 데이터

- **번들 CSV 1장**: `코드(10자리) · 이름 · 상위코드 · 계층(시도/시군구)`
- 출처: 행정표준코드관리시스템. 설정 > 정보에 출처를 표기한다.
- 이 문서의 "약 230개"는 개략치이며, **정확한 시·군·구 개수는 번들 CSV의 행 수를 단일 기준으로 삼는다.** 통계·진척률은 하드코딩된 상수가 아니라 CSV에서 계산한다.
- **지도를 제거하면서 GeoJSON이 통째로 불필요해졌다.** 이에 따라 v2에 있던 **공공누리 라이선스 리스크, GeoJSON→Path 변환 스파이크, 지도 렌더링 성능 리스크가 모두 소멸**한다. 서울 25구 → 전국 약 230개로 범위가 10배 늘어도 추가 비용이 사실상 없다.
- 앱 실행 시 CSV 무결성 1회 체크.

## 9. 내 정보

### 9.1 통계

| 지표 | 정의 |
|---|---|
| 총 캔버스 수 | 저장된 `Canvas` 전체 개수 |
| 물들인 지역 | 캔버스가 1장 이상인 시·군·구 수 `/` 전체 시·군·구 수 |
| 완성한 콜렉트북 | **하위 시·군·구가 모두 1장 이상**인 시·도 수 |
| 12색 사용 분포 | `colorIndex`별 캔버스 개수 비율 |
| 연속 기록 | 캔버스를 1장 이상 **저장한 날**이 연속된 일수 (`createdAt` 기준, 기기 로컬 타임존) |

### 9.2 설정

| 그룹 | 항목 |
|---|---|
| 알림 | 리마인더 토글·요일/시간, 이어서 작성·추억 소환·월간 결산 토글 |
| 보안 | Face ID 잠금 |
| 데이터 | iCloud 동기화 상태·사용 용량, 백업 zip 내보내기/가져오기, 캐시 정리 |
| 정보 | 행정표준코드 출처, 폰트 라이선스, 오픈소스, 개인정보 처리방침, 문의(mailto), 앱 평가(`SKStoreReviewController`), 버전 |

**Face ID 잠금이 켜져 있으면 앱 스위처 스냅샷도 가린다.** iOS는 앱을 떠날 때 미리보기용 스냅샷을 찍는데, 이걸 덮지 않으면 잠금이 무의미해진다. 덮는 시점은 **`scenePhase == .inactive`**다 — `.background`에서만 덮으면 **위로 스와이프해 앱 스위처를 여는 동안 화면이 그대로 노출된다.** 그 구간은 아직 `.background`가 아니기 때문이다. `.active`로 돌아올 때 Face ID 인증을 요구하고, 인증 전까지 커버를 유지한다.

### 9.3 로컬 알림 4종 (서버 없음 — 전부 `UNUserNotificationCenter`)

| 알림 | 트리거 | 기본값 |
|---|---|---|
| 기록 리마인더 | 사용자 지정 요일·시간 | off |
| 이어서 작성 | 임시저장 24시간 방치 시 1회 | on |
| 추억 소환 | "1년 전 오늘 ○○구에서" (해당 날짜 캔버스 존재 시) | on |
| 월간 결산 | 매월 말 "이번 달 N개 지역을 물들였어요" | on |

권한 요청은 **첫 캔버스 저장 완료 직후** 프리프롬프트 → 시스템 다이얼로그. 온보딩·첫 실행에서 묻지 않는다. 알림 인박스는 없다. **앱 기능이 알림 허용에 의존하지 않을 것** (심사 4.5.4).

## 15. 테스트

- **색 혼합 결정론** — 같은 캔버스 집합은 언제나 같은 배치를 낸다 (시드 고정 검증)
- **위치 불변성** — 캔버스를 추가해도 기존 색의 좌표가 움직이지 않는다
- 상위 6색 절단 + 인접색 흡수 로직 단위 테스트
- 레이어 JSON 인코딩 → 디코딩 라운드트립
- 회전 상태 드래그 좌표 변환
- 재편집: 저장 → 로드 → 재저장 시 레이아웃 불변
- `regionCode` 앞 2자리 == `provinceCode` 일관성
- 익스포트 결과 크기·비어있지 않음 검증
- **레이어 0개 캔버스**의 익스포트와 썸네일이 배경 틴트만으로 정상 생성되는가
- **무제목 캔버스**가 목록에서 `색이름 · 날짜`로 표시되는가
- 타입별 레이어 상한 도달 시 해당 도구가 비활성화되는가
- 누끼 타임아웃 시 `cutout` 플래그가 `false`로 원복되는가
- CloudKit 동기화 실기기 2대 수동 검증

## 16. 스파이크 (구현 전 선행)
