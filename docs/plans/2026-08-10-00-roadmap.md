# 「soozip」 구현 로드맵 — Phase 분할

> **설계 SSOT:** `docs/specs/2026-08-10-moumzip-mvp-design-v4.md`
> **도메인 컨텍스트:** `context/` (collection · canvas · editor · media · sync · profile)
> **작성일:** 2026-08-10 / **현재 상태:** 코드 0줄

이 문서는 **phase 목록과 게이트**만 정의한다. 각 phase의 태스크 단위 상세 계획은 별도 문서로 쓴다 (`docs/plans/2026-08-10-NN-phaseN-*.md`).

**뒷 phase의 상세 계획을 미리 쓰지 않는다.** Phase 0의 스파이크 결과가 Phase 3~4의 설계를 바꿀 수 있고, 확정되지 않은 것을 태스크로 적으면 폐기할 문서만 늘어난다. 각 phase는 **직전 phase의 게이트를 통과한 시점에** 상세 계획을 쓴다.

---

## 전체 목표

흰 캔버스에 사진·텍스트·도형을 자유 배치해 만든 한 장을 사용자가 만든 모음집에 담는 iOS 앱. 서버·계정 없음.

## 기술 스택

| 항목 | 선택 |
|---|---|
| 플랫폼 | iOS 17+ / Xcode 26 · iOS 26 SDK |
| UI | SwiftUI |
| 영속성 | SwiftData + CloudKit (자동 동기화) |
| 초안 | 로컬 파일 (`Application Support/Drafts/`) — **CloudKit 대상 아님** |
| 테스트 | Swift Testing (`@Test` / `#expect`), UI는 XCUITest |
| 외부 의존성 | **없음** (P0에 외부 SDK 0개) |
| 필기 | PencilKit (이미지로 베이크) |
| 폰트 | OFL 5종 번들 (서브셋) |

## 원칙

1. **TDD.** 실패하는 테스트를 먼저 쓰고, 최소 구현으로 통과시키고, 정리한다.
2. **UI 없이 테스트 가능한 것을 먼저 만든다.** Phase 1~2가 그래서 앞에 있다.
3. **phase 게이트를 넘지 않으면 다음으로 가지 않는다.** 게이트는 각 phase 하단에 정의.
4. **커밋은 태스크 단위.** 각 태스크는 독립적으로 리뷰 가능한 산출물로 끝난다.
5. **설계 변경은 v4 설계서와 `context/`에 즉시 반영한다.** 코드가 문서를 앞서가지 않는다.

## 전역 제약 (모든 phase에 적용)

v4 설계서에서 그대로 옮긴다. 태스크마다 다시 적지 않으므로 **모든 태스크의 요구사항에 이 절이 암묵적으로 포함**된다.

| 항목 | 값 |
|---|---|
| 최소 지원 | iOS 17.0 |
| 빌드 | Xcode 26 / iOS 26 SDK |
| 화면 방향 | Portrait · LandscapeLeft · LandscapeRight (Upside Down 제외) |
| 다크모드 | 미지원 — `UIUserInterfaceStyle = Light` 고정 |
| 기기 | iPhone 우선, iPad는 진행에 따라 판단 |
| 논리좌표 | 폭 **1080 고정**, 높이 **1350(4:5)** 또는 **1920(9:16)** |
| 레이어 상한 | `photo` 8 / `drawing` 5 / `text`+`shape`+`stamp` 합 30 |
| 입력 상한 | 모음집 이름 1~20자 · 캔버스 제목 0~40자 · 텍스트 레이어 200자 |
| 파스텔 12색 | `hsl(H, 55%, 82%)`, H = 0·30·60·90·120·150·180·210·240·270·300·330 |
| 캔버스 배경 | 흰색 `#FFFFFF` 고정 (P0) |
| CloudKit | 전 속성 기본값 또는 optional · `@Attribute(.unique)` 불가 · 관계는 양방향 optional · 첫 심사 후 additive-only |
| 외부 SDK | P0에서 0개 |

**파일이 커지면 쪼갠다.** 특히 `Features/Editor/`는 v4 설계의 절반을 차지하므로 Selection·SmartGuide·Tools를 처음부터 분리해 둔다.

**★ 기하 로직을 SPM 패키지로 분리한 이유가 둘이다.**
1. **플랫폼 독립** — CoreGraphics를 안 쓰므로 **Windows에서 `swift test`가 그대로 돈다.** 개발 환경이 Windows이고 Mac은 간헐적으로 쓰는 상황에서, Phase 0의 절반과 Phase 3~4의 로직 검증을 Windows에서 진행할 수 있다.
2. **테스트 속도** — Xcode 빌드 없이 몇 초 만에 돌아 Phase 4의 성능 실험 반복이 빨라진다.

대가는 `Vec2 ↔ CGPoint` 변환 어댑터(`Core/Geometry/CGInterop.swift`) 한 파일뿐이다.

## Phase 0 — 셋업 + 스파이크

**왜 먼저인가:** S1(제스처·선택 UI·스마트 가이드)이 v4 최대 기술 리스크다. 여기서 접근이 깨지면 Phase 3~5 설계를 다시 해야 하므로, **에디터 본체를 만들기 전에 찔러본다.**

**실행 환경이 둘로 갈린다.**

| 구간 | 내용 | 환경 |
|---|---|---|
| **A** | `SoozipGeometry` 패키지 — Vec2 · LayerFrame · ResizeAnchor · SnapEngine | **Windows 가능** |
| **B** | Xcode 프로젝트 + 패키지 통합 + 스파이크 3건 | **macOS 필수** |

**산출물**
- `Packages/SoozipGeometry/` — 26개 단위 테스트로 검증된 기하 로직 (**영구 자산**)
- Xcode 프로젝트 + 테스트 타깃 + 폴더 구조 + `CGInterop`
- 전역 제약 적용 (방향·Light 고정·최소 버전)
- 스파이크 3건의 **결과 보고서** (`docs/reports/2026-08-10-spike-results.md`)

**스파이크 3건**

| # | 검증 대상 | 통과 기준 |
|---|---|---|
| **S1** | 제스처 · 선택 UI · 스마트 가이드 | 회전 45° 레이어의 코너 핸들 드래그가 대각 고정점을 유지 · 줌 200%에서 핸들 히트 영역 44pt 유지 · 레이어 43개에서 드래그 중 **60fps 유지** · 선택 유무에 따라 핀치가 레이어/캔버스로 갈림 |
| **S2** | SwiftData + CloudKit | 실기기 2대 양방향 동기화 · **초안 폴더가 동기화되지 않음** · 기본값/optional 제약 하에서 관계 정상 |
| **S3** | 폰트 번들 | 5종 서브셋 후 **총 10MB 이하** · 로드 시간 · 한글 글리프 누락 없음 |

**게이트 (통과해야 Phase 1 진입)**
- [ ] `SoozipGeometry` 26개 테스트가 **Windows와 macOS 양쪽에서** 통과한다 (결과가 다르면 플랫폼 의존이 새어 들어간 것)
- [ ] 패키지에 CoreGraphics·SwiftUI import가 하나도 없다
- [ ] S1의 4개 기준을 **실측 수치와 함께** 보고서에 기록. 60fps가 안 나오면 대안(핸들 렌더 방식 변경 / 가이드 계산 스로틀링)을 결정하고 v4 설계서 §5.8.4를 수정
- [ ] S2에서 실기기 2대 동기화 확인. 실패 시 모델 구조 수정 후 재검증
- [ ] S3에서 용량 초과 시 폰트를 3종으로 줄이거나 ODR 전환을 결정하고 §5.5를 수정
- [ ] **UI 프로토타입(`Soozip/Spikes/`)은 폐기**하고 결과만 남긴다. 단 `Packages/SoozipGeometry/`와 `CGInterop.swift`는 **유지한다** — 검증된 자산이며 Phase 3~4가 그 위에 세워진다

## Phase 1 — 데이터 레이어

**목표:** UI 없이 단위 테스트만으로 완성되는 영속성 계층.

**산출물**
- `Collection` · `Canvas` · `CanvasPhoto` 모델 (CloudKit 제약 준수)
- 리포지토리 — 쿼리 · 표지 재계산 3지점 · `sortIndex` 타이브레이크
- 로컬 모드 격하 감지

**게이트**
- [ ] 모델 3종의 CloudKit 제약 체크리스트 통과 (기본값/optional · unique 없음 · 양방향 optional · 배열 속성 없음)
- [ ] **표지 재계산 3지점**(저장 / 삭제 / 모음집 이동) 단위 테스트 통과
- [ ] `sortIndex` 중복 시 `createdAt` 타이브레이크 테스트 통과
- [ ] cascade 삭제 테스트 통과 (모음집 → 캔버스 → 사진)
- [ ] 실기기 2대 동기화 재확인

## Phase 2 — 초안 저장소

**목표:** 저장 트랜잭션의 안전성. **작업물이 절대 증발하지 않는다.**

**산출물**
- ~~`Drafts/<uuid>/` 파일 I/O~~ → **선행 완료** (`Packages/SoozipDraft`, 테스트 24) — `meta.json` 추가, 고아 정리 포함
- ~~layoutJSON v1 인코딩·디코딩~~ → **선행 완료** (`Packages/SoozipLayout`, 테스트 40)
- 1.5초 디바운스 자동 저장 — 타이머는 앱 계층. `DraftStore.writeLayout`을 호출한다
- **승격 트랜잭션 7단계** ← Mac 필요 (SwiftData 쓰기 단계 포함). Phase 2의 남은 핵심
- 앱 시작 시 `pruneOrphans` 호출 배선

**게이트**
- [ ] **저장 실패 시 초안이 보존되는가** — 2~5단계 각각을 강제 실패시켜 검증
- [ ] 저장 성공 시에만 `Drafts/` 폴더가 삭제되는가
- [ ] 재편집 취소 시 원본 `Canvas`와 `renderedPNG`가 변하지 않는가
- [ ] layoutJSON 라운드트립 (레이어 5종 전부, 캔버스 밖 좌표 포함)
- [ ] 고아 초안 정리 (무소속 / 7일 초과)
- [ ] 초안이 CloudKit에 올라가지 않는가 (실기기 2대)

## Phase 3 — 에디터 코어

**목표:** 레이어를 놓고 옮기고 키우고 돌린다. **도구는 아직 없다** — 테스트용 더미 레이어로 조작만 완성한다.

**산출물**
- 캔버스 표면 (논리좌표 → 화면 변환, 클리핑, 흰 배경)
- 레이어 5종 렌더러 (공통 조작 경로)
- 선택 UI — 바운딩 박스 · 코너 4 · 변 · 회전 · 삭제 핸들
- 제스처 우선순위 · 캔버스 줌(50~400%) · 팬
- 캔버스 경계 · 고스트 · 작업 영역 제한
- z-order 4종

**게이트**
- [ ] 회전 0°·45°·90° 각각에서 코너 핸들 드래그 시 대각 고정점 유지
- [ ] 변 핸들이 `photo`·`stamp`·`drawing`에 나타나지 않음
- [ ] 크기 하한 40px · 상한 캔버스 긴 변 ×4에서 정지
- [ ] 핸들 겹침 방지 단계(88pt / 56pt) 동작
- [ ] 줌 200%에서 핸들 화면 크기·히트 영역이 100%와 동일
- [ ] 캔버스 밖 레이어가 잘려 보이고 다시 넣으면 온전히 복원
- [ ] 레이어 중심이 작업 영역 밖으로 못 나감
- [ ] 기기 회전 시 논리좌표 불변 · 줌 배율만 재계산
- [ ] z-order 4종 후 z가 0부터 촘촘히 재정렬

## Phase 4 — 스마트 가이드

**목표:** 눈대중으로 못 맞추는 정렬을 진동으로 알려준다.

**산출물**
- 정렬 가이드 (캔버스 중심선 + 다른 레이어 6기준선)
- 균등 간격 가이드 (3개 이상)
- 크기 일치 가이드 (리사이즈 중)
- 회전 15° 스냅
- 햅틱 4종 구분

**게이트**
- [ ] 각 가이드가 올바른 지점에서만 발화 (오탐 없음)
- [ ] 회전된 레이어가 정렬·간격 후보에서 제외됨
- [ ] 동시 다중 히트 시 햅틱 1회 · enter 이벤트에만
- [ ] 스냅 임계가 줌 배율과 무관하게 화면 8pt
- [ ] **레이어 43개에서 드래그 중 60fps 유지** (S1 실측치 대비 회귀 없음)

## Phase 5 — 에디터 도구

**목표:** 실제로 캔버스를 채울 수 있게 된다. 이 phase 끝에서 **첫 결과물이 나온다.**

**산출물**
- 도구 7종 (사진 · 텍스트 · 도형 · 날짜 도장 · 펜 · 배경(비활성) · 필터)
- 폰트 5종 번들 + 스와치
- 도형 9종 × 파스텔 12색 + 마지막 색 기억
- 복제 (전 타입) · 클립보드 붙여넣기
- **알파 파이프라인** — 판정 · `opaque=false` · 포맷 분기 · 트림
- 레이어 상한 + 도구 비활성화

**게이트**
- [ ] **투명 배경 이미지의 4시점 검증** — 붙여넣기 직후 / 저장 직후 / 앱 재실행 후 / 재편집 진입 후 모두 투명 유지
- [ ] 리사이즈가 `opaque = false`로 수행됨
- [ ] 알파 채널은 있으나 전부 불투명한 이미지(스크린샷)는 JPEG로 저장
- [ ] 사진 복제가 `assetId`를 공유해 `CanvasPhoto`가 늘지 않음
- [ ] 복제본 하나를 지워도 나머지가 참조하는 `CanvasPhoto`가 남음
- [ ] 타입별 상한 도달 시 도구·[복제] 비활성화
- [ ] 폰트 5종 로드 + 실패 시 시스템 폰트 폴백
