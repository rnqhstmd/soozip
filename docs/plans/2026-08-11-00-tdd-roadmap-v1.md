# soozip v1 로드맵 — 도메인별 TDD 단위 분할

- 작성일: 2026-08-11
- 대체 대상: `2026-08-10-00-roadmap.md`의 Phase 2~9 분할 (Phase 목록·전역 제약·리스크표는 그대로 유효)
- 설계 SSOT: `docs/specs/2026-08-10-moumzip-mvp-design-v4.md`

## 왜 다시 나누는가

기존 로드맵은 **Phase 단위**로 나뉘어 있었다. Phase 1·2·6을 실제로 돌려 보니 두 가지가 드러났다.

1. **Phase는 TDD 사이클의 단위로 너무 크다.** Phase 1이 RGR 9사이클, Phase 6이 6사이클이었다. "Phase 3 에디터 코어"는 게이트만 9건이라 착수 시점에 어디부터 잡을지가 매번 즉흥이 된다.
2. **"S1이 막는다"가 실제보다 크게 잡혀 있었다.** 에디터 게이트 9건 중 실기기가 정말 필요한 것은 **fps 하나**다. 나머지는 기하·상태·히트 판정이라 전부 로직 테스트로 덮인다.

그래서 **도메인별 TDD 단위**로 다시 나눈다. 각 단위는 RGR 1~2사이클 크기이고, 테스트로 덮이는지 여부를 명시한다.

## v1 범위 결정 (2026-08-11)

**CloudKit을 v1에서 제외한다.** 1차 출시 후 고도화로 넘긴다.

- **잃는 것은 기기 2대 동시 사용 하나뿐이다.** 기기 교체는 iOS 기기 백업이 커버한다 — SwiftData 스토어는 Application Support에 있어 백업에 포함된다. iCloud 동기화와 iOS 백업은 다른 것이다
- **나중에 켤 수 있다.** 스키마 동결은 "CloudKit을 켠 채 프로덕션 배포한 시점"부터 시작되므로, 안 켜고 출시하면 동결도 없다. 기존 로컬 스토어를 CloudKit 미러링으로 전환하는 전제 조건이 **우리가 이미 지키고 있는 제약**(전 속성 기본값/optional·unique 없음·양방향 관계)이고 `ModelSchemaTests`가 강제한다
- **v2 착수 전 필수 실측**: 기존 로컬 스토어 → CloudKit 전환이 데이터 손실 없이 되는가
- **열려 있는 차단 조건**: `DraftMaintenance.pruneOrphanedDrafts`가 CloudKit 부분 임포트 중 살아있는 초안을 지운다. CloudKit을 켜기 전 반드시 닫는다 (`.dev/feat-draft-pruning/trust-ledger.md`)

**Phase 4(스마트 가이드)와 Phase 8(검색·통계·알림)을 v1.1로 미룬다.** 없어도 캔버스는 만들어지고, 심사 4.5.4가 "알림 없이 전 기능 동작"을 요구하므로 알림은 애초에 필수가 아니다.

## 명명 규약

**단위 ID에 도메인 접두사를 붙인다** — `CANVAS-3`, `EDITOR-5`. AC도 같은 규약을 쓴다(`EDITOR-5 AC-2`).

이유: Phase 1과 Phase 6이 각자 `AC-14`를 갖는 바람에 `LibraryRepositoryTests.swift` 한 파일에 같은 번호가 두 뜻으로 공존하는 일이 실제로 벌어졌다. 테스트가 어느 스펙의 어느 조건을 재는지 읽는 사람이 알 수 없다.

### ⚠️ 에디터가 `promote()`를 배선하기 전에 처리할 것

`CanvasPromoter`는 아직 **테스트에서만 생성된다.** 저장 버튼에 배선하는 순간
아래 둘이 살아난다 (`.dev/feat-canvas-photo-ownership/trust-ledger.md` 참조).

| 항목 | 무엇 | 어디서 |
|---|---|---|
| ~~**멱등성 가드**~~ | ~~같은 초안을 두 번 승격하면 같은 `id`의 `Canvas`가 둘 생긴다~~ → **처리됨.** `promote`가 렌더보다 먼저 `alreadyPromoted`로 거부한다 | ✅ |

**`CANVAS-6`(재편집 세션)은 이제 재승격 처리를 침묵으로 넘길 수 없다** — 가드가
거부로 막고 있으므로, 재편집 저장 경로는 "거부"를 "갱신"으로 바꾸는 결정을
명시적으로 해야 한다. 가드를 지금 넣은 이유가 이것이다.

## editor — 레이어 조작 (v1 필수)

**게이트 9건 중 실기기가 필요한 것은 fps 하나뿐이다.** 나머지는 기하·상태라 로직으로 덮인다.
`SoozipGeometry`(테스트 50개)에 `LayerFrame`·`resized`·`toLocal`/`toWorld`·`corner`·`CanvasSurface`가 있다.

**`CanvasSurface`는 배율·뷰포트에 독립인 것만 저장한다** — `zoom`은 fit 대비 배수,
`center`는 뷰포트 중앙에 오는 논리 지점. 그래서 기기 회전 경로에 보정 코드가 없다.
`EDITOR-5`(핸들 화면 크기 고정)·`EDITOR-9`(경계)·`EDITOR-10`(제스처)이 이 변환을 입력으로 쓴다.
**`EDITOR-9`는 `workArea`·`clampedToWorkArea`를 그대로 쓴다** — 팬 한계와 레이어 한계는 같은 사각형이라 두 벌로 갈라지면 조용히 어긋난다.
