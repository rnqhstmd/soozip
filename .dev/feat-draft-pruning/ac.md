# 고아 초안 정리 앱 시작 배선 — AC

- 작성일: 2026-08-11
- 모드: 핵심(core) / 표준 프로파일
- 브랜치: `feat/draft-pruning` (base `main`)

## 배경

`DraftStore.pruneOrphans(knownCollectionIDs:now:maxAge:)`는 `Packages/SoozipDraft`에 이미 있고 테스트 24개로 검증돼 있다. **없는 것은 그것을 부르는 자리다.** 정리하지 않으면 사진 사본이 계속 쌓여 사용자가 원인을 알 수 없는 용량을 먹는다(v4 §6.9).

Phase 1이 끝나면서 인자를 채울 수단이 생겼다 — `LibraryRepository.collections()`가 `knownCollectionIDs`를 준다. 이 배선이 Phase 2에서 S2 스파이크에 막히지 않는 유일한 항목이다.

### 이 작업의 핵심 위험

`pruneOrphans`는 **`knownCollectionIDs`에 없는 소속을 가진 초안을 지운다.** 따라서:

```
모음집 조회 실패 → 빈 Set 전달 → 전 초안이 고아로 판정 → 사용자 작업물 전량 삭제
```

조회 **실패**와 모음집이 **정말 0개**인 것은 다르다. 후자는 초안이 실제로 고아이므로 지우는 게 맞고, 전자는 아무것도 지우면 안 된다. 이 구분이 이 작업의 전부다.

## 요구사항

- FR-1: 앱 시작 시 고아 초안을 1회 정리한다.
- FR-2: 소속 모음집이 존재하지 않거나 마지막 수정 후 7일이 지난 초안을 지운다. (판정 자체는 `DraftStore`가 이미 한다)
- FR-3: **모음집 조회가 실패하면 정리를 건너뛴다.** 실패를 "모음집 0개"로 접지 않는다.

## 수용 기준

- **AC-1**: Given 모음집 A가 존재하고 A에 속한 초안 1개와 삭제된 모음집 Z에 속한 초안 1개가 있을 때, When 정리를 실행하면, Then Z의 초안만 삭제되고 A의 초안은 남는다.

- **AC-2**: Given 모음집 A에 속한 초안이 마지막 수정 후 8일이 지났을 때, When 기준 시각을 오늘로 하여 정리를 실행하면, Then 그 초안이 삭제된다.

- **AC-3**: Given 모음집 A에 속한 초안이 마지막 수정 후 6일이 지났을 때, When 기준 시각을 오늘로 하여 정리를 실행하면, Then 그 초안이 남는다.

- **AC-4**: Given 모음집 조회가 실패하는 상태에서 초안 2개가 존재할 때, When 정리를 실행하면, Then 초안이 하나도 삭제되지 않고 조회 실패가 호출부로 전달된다.

- **AC-5**: Given 모음집이 0개이고 초안 1개가 존재할 때, When 정리를 실행하면, Then 그 초안이 삭제된다(소속이 실재하지 않으므로 고아가 맞다).

## 범위 밖

- **승격 트랜잭션 7단계** — S2 스파이크(초안 미동기화 검증)가 전제라 착수하지 않는다.
- **1.5초 디바운스 자동 저장** — 호출부가 에디터(Phase 3)라 부르는 데가 없다.
- 초안 배너("이어서 만들까요?") 등 UI — Phase 6.
