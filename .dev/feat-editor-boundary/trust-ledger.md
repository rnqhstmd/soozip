# Trust Ledger — EDITOR-9 (캔버스 경계와 레이어 이탈)

## 통합 감사 (review)

**security-auditor 판정: CRITICAL 0 · HIGH 0 · MEDIUM 5.** 이 앱은 로컬 전용이라 서버·인증·네트워크 취약점 축이 없다. 감사는 이 저장소의 실제 위험 축(작업물 증발 · 레이어 유실 · 미검증 가정 · 단일 출처 규약)에 집중했다.

### [ASSUMPTION/MEDIUM] `canvasCenter` 유한성이 강제되지 않는다 → **문서화 + 이월 결정**

- **근거**: `clampedLayerCenter`는 입력 `p`만 방어하고 `canvas` 유효성은 검사하지 않는다. 자매 함수 `overlap(canvas:)`는 검사한다(FR-3). `LayoutDocument.init(from:)`이 `canvas.w`/`h`를 `isFinite`·`> 0` 검증 없이 디코딩하므로(`Packages/SoozipLayout/Sources/SoozipLayout/LayoutDocument.swift`) `{"w": 0, "h": 1350}` 문서로 도달 가능하고, 그러면 `workArea`가 `x = 0`인 **수직 선분**(`y ∈ [-675, 2025]`)으로 납작해져 모든 레이어 중심의 x가 `0`으로 붕괴한다. `{"w": 0, "h": 0}`이면 **한 점 `(0,0)`**이 되어 전부 그 점으로 뭉개진다 — 크래시는 없지만 "영영 못 잡음"과 사실상 같은 기능 붕괴. (⚠️ 초안은 이것을 `{"w":0}`만으로 "한 점"이라 적었는데 과장이었다. 2회차 quality 리뷰가 잡았다.)
- **결정(사용자)**: 가드를 추가하지 않고 **신뢰 경계 차이로 문서화**한다. `overlap(canvas: Size2)`는 **임의의 인자**를 받아 호출부가 실수로 `viewport`를 넘길 수 있지만(둘 다 `Size2`), `clampedLayerCenter`는 **생성 시 확정된 자기 상태**를 읽는다. 검증은 값이 들어오는 **디코딩 경계에서 한 번** 하는 것이 옳고 그것은 `SoozipLayout` 소관이다.
- **이월**: `LayoutDocument`의 `canvas` 디코딩 검증(`isFinite && > 0`, 실패 시 `DecodingError`). **수신: `CANVAS` 도메인 또는 `SoozipLayout` 후속 단위.** 근거는 `LayerCenterClamp.swift` doc에 기록됨.

### [GAP/MEDIUM] `ResizeAnchor` 인계 주석 미갱신 → **해소됨**

PRD 판단 7이 `ResizeAnchor.swift:90-92`의 인계(*"0폭 레이어 복구 … `EDITOR-9`/`EDITOR-11`로 넘긴다"*)를 명시적으로 거절했는데 소스 주석이 그대로였다. 주석을 갱신해 **수신자를 `EDITOR-11` 하나로** 좁혔다.

### [GAP/MEDIUM] 회전 오차 문단에 인계 제약 미재언급 → **해소됨**

`.partial`을 렌더 트리거·사용자 신호로 쓰지 말라는 제약이 doc 상단 계약 문단에만 있어, 회전 오차 문단만 읽으면 놓칠 수 있었다. 해당 문단 말미에 재언급 추가.

### [GAP/MEDIUM] `Interval` 빈 배열 사전조건 부재 → **계약 문서화로 해소**

빈 배열이면 뒤집힌 빈 구간(`lower=+∞, upper=−∞`)이 되어 `contains`가 공허하게 참이 된다(NaN 경로와 같은 실패 모드, 다른 진입점). **현재 도달 불가**(호출부 둘 다 4점 리터럴, `private`). `precondition`을 넣지 **않았다** — 도달 불가 분기에 트랩을 넣으면 증인 없는 코드가 늘어난다. 계약만 doc에 남겼다.

### [GAP/MEDIUM] BR-5 호출부 0건 → **알려진 이월 재확인**

`clampedLayerCenter` 호출자가 테스트뿐이다. 이 시점에 앱의 어떤 실제 경로도 레이어 중심을 제한하지 않는다. PRD 판단 4가 이미 이월했고, **`EDITOR-10` 착수 전 실패하는 플레이스홀더 테스트로 게이트를 세울 것**을 권고한다.

## 코드 품질 (quality-reviewer)

**판정: Critical 0 · Important 1 · Minor 3.** Important는 전부 `[동작불변]`이라 프로덕션 코드 변경 없이 닫혔다.

### Important 1건 — **해소됨**

**테스트 주석이 프로덕션 설계 원장과 정반대 사실을 단정했다.** `LayerBoundaryTests.swift`의 `레이어_값이_하나라도_비유한이면_완전히_밖이다` 주석이 *"이 테스트는 유한성 가드의 증인이 아니다 … 가드를 지워도 전부 `.outside`"*라고 적혀 있었는데, 프로덕션 doc은 정반대(*"증인이 있다 … `.inside`가 된다"*)였고 **프로덕션 쪽이 맞았다**.

**영향이 주석에 그치지 않는다** — 이 주석을 읽은 다음 사람은 (a) 가드를 "증인 없는 중복 방어"로 판단해 지우거나(결과는 `.inside`, 세 값 중 가장 위험한 오판), (b) 이 테스트를 무효 단언으로 지운다(킬셋 16종 중 1종이 무증인이 된다). 주석을 사실로 교체했다.

### Minor 3건 — 2건 해소, 1건 이월

- **해소**: `Interval` 빈 배열 계약 (위 GAP과 동일 건)
- **해소**: *"첫 원소가 0이라"*는 설명이 부정확 — 씨앗값 접기에서는 순서가 무관하고 비-NaN이 하나라도 있으면 그것이 남는다(실측 확인). 정확한 이유로 교체.
- **이월**: `overlap(canvas:)` 호출 1회당 배열 10개 힙 할당(점 배열 2 + `Interval.init`마다 `map` 1 × 8). `EDITOR-11`이 프레임마다 레이어 수만큼 부르면 누적된다. ⚠️ **고칠 때 `±∞` 씨앗값 접기 형태를 반드시 보존할 것** — 수동 루프로 바꾸며 첫 원소를 씨앗으로 삼으면 레이어 유한성 가드의 증인이 조용히 사라진다. **수신: `EDITOR-11`** (측정은 `SnapBench` 형식으로).
