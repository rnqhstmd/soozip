# Phase 6 — 모음집 화면 PRD

- 작성일: 2026-08-11
- 모드: 전체(all) / 표준 프로파일
- 브랜치: `feat/collection-screen` (base `main`)
- 설계 SSOT: `docs/specs/2026-08-10-moumzip-mvp-design-v4.md` §2.2, §4, §12

## 배경

Phase 1이 리포지토리를, Phase 2가 초안 정리 배선을 끝냈다. **아직 앱에는 화면이 하나도 없다** — 루트가 Phase 0 제스처 프로브다.

Phase 6은 이 앱의 첫 화면을 만든다. 사용자가 모음집을 만들고, 보고, 정리하는 경로 전부다.

### 지금 만들 수 없는 것을 먼저 밝힌다

**캔버스를 만드는 유일한 경로가 에디터(Phase 3~5)다.** 따라서 이번 범위에서:

- 표지·캔버스 그리드·초안 배너는 **로직만 테스트로 검증**하고 화면 확인은 Phase 3 이후로 미룬다
- 테스트는 `Canvas`·`CanvasPhoto`·초안 폴더를 직접 만들어 픽스처로 쓴다
- 실제로 눈으로 확인 가능한 것은 모음집 CRUD·캐러셀·빈 상태·재배치다

에디터가 붙는 순간 나머지에 불이 들어오도록, **표시할 값을 만드는 로직을 뷰 밖에 두는 것**이 이번 설계의 핵심 제약이다.

## 범위

| 산출물 | 내용 |
|---|---|
| 캐러셀 | 가로 스크롤 · 맨 좌측 [+] 고정 · 카드(표지 + 이름 + 캔버스 수) |
| 전체 보기 | 모음집 그리드 — 캐러셀이 길어졌을 때의 탈출구 |
| 카드 컨텍스트 메뉴 | 이름 변경 / 대표 캔버스 변경 / 순서 이동 / 삭제 |
| 모음집 상세 | 캔버스 그리드(최신순/오래된순) + 초안 배너 |
| 생성 | [+] → 이름 입력 시트 → **생성 즉시 상세로 진입** |
| 삭제 | 캔버스가 있으면 **개수를 명시해 경고** 후 cascade |
| 첫 실행 | 고스트 힌트("첫 모음집을 만들어보세요", 탭하면 사라짐) |

## 제외 범위

| 항목 | 어디로 |
|---|---|
| 통합 검색(모음집 이름 + 캔버스 제목) | Phase 8 |
| 탭2「내 정보」·탭 셸 | Phase 8 |
| [+] → 비율 시트 → PHPicker → 에디터 | Phase 3 |
| 캔버스 뷰어(전체화면·좌우 스와이프) | Phase 7 |
| 샘플 모음집 자동 생성 | Phase 9 (§12, 저작권 정리된 이미지 필요) |

## 기능 요구사항

- FR-1: 모음집을 생성 순서대로 가로 캐러셀에 표시한다. 맨 좌측에 [+] 카드를 고정한다.
- FR-2: 카드는 표지·이름·캔버스 수를 보여준다. 캔버스가 0장이면 연한 단색 카드 + 이름만.
- FR-3: 표지는 지정된 대표 캔버스 → 가장 최근 캔버스 → 단색 순으로 폴백한다.
- FR-4: 「전체 보기」로 모음집 그리드에 진입할 수 있다.
- FR-5: 카드를 길게 눌러 이름 변경·대표 캔버스 변경·순서 이동·삭제를 할 수 있다.
- FR-6: 모음집을 길게 눌러 드래그하면 순서가 `sortIndex`로 고정된다.
- FR-7: 모음집 상세에서 캔버스를 최신순 또는 오래된순 그리드로 본다.
- FR-8: 해당 모음집에 초안이 있으면 상세 상단에 "이어서 만들까요?" 배너를 띄운다.
- FR-9: [+]로 이름을 입력해 모음집을 만들면 즉시 그 모음집 상세로 진입한다.
- FR-10: 모음집 삭제 시 안에 캔버스가 있으면 **개수를 명시해** 경고한 뒤 cascade 삭제한다.
- FR-11: 모음집이 하나도 없으면 고스트 힌트를 보여주고, 탭하면 사라진다.

## 비즈니스 규칙

- BR-1: 이름은 필수, 1~20자. 중복 허용. (리포지토리가 이미 강제 — Phase 1)
- BR-2: 표지 지정은 `coverCanvasID`에 쓴다. **그 모음집에 속하지 않은 캔버스는 표지가 될 수 없다.**
- BR-3: 표지 이미지를 디코딩할 수 없으면(손상·빈 데이터) 단색 카드로 폴백한다. 빈 화면을 내지 않는다.
- BR-4: 재배치는 보이는 순서를 그대로 `sortIndex` 0..n-1로 다시 매긴다.
- BR-5: 고스트 힌트는 한 번 닫으면 다시 뜨지 않는다. 모음집을 전부 지워도 다시 뜨지 않는다.

## 수용 기준

### 캐러셀과 카드 (FR-1·2·3)

- **AC-1**: Given 모음집 3개가 생성 순서 가·나·다로 있을 때, When 캐러셀을 구성하면, Then 항목이 [+], 가, 나, 다 순서로 나온다.
- **AC-2**: Given 모음집이 하나도 없을 때, When 캐러셀을 구성하면, Then 항목이 [+] 하나뿐이다.
- **AC-3**: Given 캔버스가 0장인 모음집일 때, When 카드 표시값을 만들면, Then 표지가 `.empty`(단색)이고 캔버스 수가 0이다.
- **AC-4**: Given 모음집에 `renderedPNG`를 가진 캔버스 2장이 있고 표지가 지정되지 않았을 때, When 카드 표시값을 만들면, Then 표지 이미지가 **가장 최근 캔버스**의 것이다.
- **AC-5**: Given 모음집에 캔버스 3장이 있고 그중 가장 오래된 것이 대표로 지정됐을 때, When 카드 표시값을 만들면, Then 표지 이미지가 **지정된 그 캔버스**의 것이다(최신이 이기지 않는다).
- **AC-6**: Given 표지 캔버스의 `renderedPNG`가 디코딩 불가능한 바이트일 때, When 카드 표시값을 만들면, Then 표지가 `.empty`로 폴백되고 캔버스 수는 실제 값을 유지한다.
- **AC-7**: Given 캔버스 5장을 가진 모음집일 때, When 카드 표시값을 만들면, Then 캔버스 수가 5다.

### 대표 캔버스 지정 (FR-5, BR-2)

- **AC-8**: Given 모음집 A에 캔버스 C1·C2가 있을 때, When C2를 A의 대표로 지정하면, Then A의 `coverCanvasID`가 C2의 식별자가 된다.
- **AC-9**: Given 모음집 A와 B가 있고 캔버스 C가 B에 속할 때, When C를 A의 대표로 지정하려 하면, Then 거부되고 A의 `coverCanvasID`가 변하지 않는다.

### 이름 변경 (FR-5)

- **AC-10**: Given 이름이 "여행"인 모음집일 때, When 이름을 "제주"로 바꾸면, Then 이름이 "제주"가 되고 `sortIndex`와 `coverCanvasID`는 변하지 않는다.
- **AC-11**: Given 모음집이 있을 때, When 21자 이름으로 변경을 시도하면, Then 거부되고 원래 이름이 유지된다.

### 순서 재배치 (FR-6, BR-4)

- **AC-12**: Given 모음집이 가·나·다 순일 때, When 다를 맨 앞으로 옮기면, Then 조회 순서가 다·가·나가 된다.
- **AC-13**: Given 모음집이 가·나·다 순일 때, When 다를 맨 앞으로 옮기면, Then 세 모음집의 `sortIndex`가 각각 0·1·2로 다시 매겨진다.

### 전체 보기 (FR-4)

- **AC-14**: Given 모음집 3개가 있을 때, When 전체 보기 목록을 구성하면, Then 캐러셀과 **같은 순서**의 카드 3개가 나오고 [+] 항목은 포함되지 않는다.

### 모음집 상세 (FR-7)

- **AC-15**: Given 모음집에 기록 날짜가 다른 캔버스 3장이 있을 때, When 상세를 최신순으로 구성하면, Then 최신 → 오래된 순으로 나온다.
- **AC-16**: Given 같은 상황에서, When 오래된순으로 전환하면, Then 순서가 정확히 뒤집힌다.
- **AC-17**: Given 모음집 A와 B에 각각 캔버스가 있을 때, When A의 상세를 구성하면, Then B의 캔버스는 섞이지 않는다.

### 초안 배너 (FR-8)

- **AC-18**: Given 모음집 A에 속한 초안이 있을 때, When A의 상세를 구성하면, Then 배너가 노출된다.
- **AC-19**: Given 모음집 A에 초안이 없고 모음집 B에는 있을 때, When A의 상세를 구성하면, Then 배너가 노출되지 않는다.

### 생성 (FR-9)

- **AC-20**: Given 모음집이 2개 있을 때, When "제주"라는 이름으로 생성하면, Then 3번째로 추가되고 생성된 모음집이 결과로 반환된다(즉시 상세 진입의 근거).
- **AC-21**: Given 생성 시트에서, When 빈 이름으로 생성을 시도하면, Then 거부된다.

### 삭제 (FR-10)

- **AC-22**: Given 캔버스 3장을 가진 모음집일 때, When 삭제 확인 문구를 만들면, Then 문구에 **3**이 포함된다.
- **AC-23**: Given 캔버스가 0장인 모음집일 때, When 삭제 확인이 필요한지 판정하면, Then 경고 없이 즉시 삭제 가능으로 판정된다.
- **AC-24**: Given 캔버스 2장과 각 캔버스에 사진 2장이 있는 모음집일 때, When 삭제하면, Then 모음집·캔버스 2개·사진 4개가 모두 조회되지 않는다.

### 첫 실행 힌트 (FR-11, BR-5)

- **AC-25**: Given 모음집이 0개이고 힌트를 닫은 적이 없을 때, When 힌트 노출 여부를 판정하면, Then 노출로 판정된다.
- **AC-26**: Given 모음집이 1개 이상일 때, When 힌트 노출 여부를 판정하면, Then 비노출로 판정된다.
- **AC-27**: Given 힌트를 한 번 닫은 뒤 모음집을 전부 지웠을 때, When 힌트 노출 여부를 판정하면, Then 비노출로 판정된다.

## 확정된 사항

- **앱 루트는 모음집 화면이 된다. 스파이크는 `#if DEBUG` 진입점으로 남긴다.** 로드맵이 "S1·S2 측정이 끝나기 전에는 지우지 않는다"고 했고 측정하려면 실행 가능해야 하는데, 릴리스 빌드에 프로브가 실려서도 안 된다. DEBUG 전용 진입점이 둘을 모두 만족한다.
  - **AC-28**: Given 릴리스 구성으로 빌드할 때, When 앱 진입점을 구성하면, Then 스파이크 진입 경로가 포함되지 않는다.
- **탭 셸은 만들지 않는다.** 모음집 화면이 곧 루트다. 탭 하나짜리 `TabView`는 의미가 없고, 이 프로젝트는 호출부가 생길 때 만든다는 원칙을 지켜 왔다(Phase 1에서 `renameCollection`·`reorderCollections`를 미룬 것이 이번에 값을 했다). 탭 셸은 Phase 8이 탭2를 만들 때 함께 세운다.

## 설계 단계로 넘기는 문제

**대표 캔버스 지정이 Phase 1의 컨벤션과 정면으로 만난다.** Phase 1은 "`coverCanvasID`에 대입하는 유일한 지점은 `CoverPolicy.reconcile`"을 못박았는데, 그 근거는 대입 지점이 흩어지면 케이싱이 다른 값이 섞여 표지가 조용히 사라진다는 것이었다. 사용자 지정은 새로운 대입 경로를 요구한다.

규약을 깨지 않으면서 지정을 지원하는 방법(예: `CoverPolicy`에 지정 경로를 추가하고 여전히 그 안에서만 대입)을 설계에서 정한다. AC-8·9가 이 결정의 검증 조건이다.
