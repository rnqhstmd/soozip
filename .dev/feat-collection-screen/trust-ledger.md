# Trust Ledger — Phase 6 모음집 화면

- 작성일: 2026-08-11
- 모드: 전체(all) / 표준 프로파일

## 보안 감사

이 변경은 화면 계층이다. 네트워크·자격증명·역직렬화 표면이 없고, 파일을 쓰는
경로도 없다. 실질적 위험은 **삭제**와 **표지 이미지 디코딩** 둘이다.

### [HIGH] 모음집 삭제가 캔버스와 사진까지 지운다 — 방어됨

- 0장만 즉시 삭제이고 1장부터는 개수를 명시해 확인을 받는다(`DeletionPrompt`)
- 문구를 값이 들고 있어 "N이 실제 개수인가"가 테스트로 측정된다
- cascade 자체는 Phase 1이 `deleteRule` 단독으로 검증했고, 화면이 부르는 경로가
  그 cascade에 닿는지를 이번에 다시 확인했다(AC-24)

### [MEDIUM] 신뢰할 수 없는 바이트를 이미지로 그린다 — 방어됨

`renderedPNG`는 CloudKit을 거쳐 다른 기기에서 올 수 있고, 손상된 채 도착할 수 있다.
디코딩 실패를 그대로 두면 빈 화면이 나온다.

- 프레젠터가 `canDecodeImage`로 **미리 걸러** `.image`에는 디코딩 가능이 확인된
  데이터만 담는다(BR-3, AC-6)
- 판정을 주입받으므로 실패 경로가 테스트로 측정된다
- `UIImage(data:)`는 파싱 실패 시 `nil`을 낼 뿐이고 이 계층은 그 결과만 쓴다

### [정보] 상세 화면의 `try?` 두 곳 — 의도적

초안 배너 조회와 삭제 실행이 실패를 삼킨다. 배너는 "없다고 보는" 쪽이 안전하고
(없는 초안을 있다고 하면 사용자가 작업물이 사라졌다고 읽는다), 삭제 실패는
목록이 그대로 남아 사용자가 재시도할 수 있다. 로깅 기반이 없어 기록할 곳도 없다 —
Phase 9에서 재검토.

않았다. 캐러셀 바로 아래 흐름으로 옮겼다.

## 위험 수용

- [AC-28 자동 검증 불가] "릴리스 빌드에 스파이크 진입 경로 없음"은 `#if DEBUG`
  컴파일 타임 분기인데 테스트 자체가 DEBUG에서 돈다. `SpikeMenu.swift` 파일
  전체를 `#if DEBUG`로 감싸는 것으로 대응하고, 확인은 코드 리뷰에 맡긴다 (design)
- [뷰 계층 테스트 미적용] SwiftUI 뷰·앱 루트 배선은 자동 검증 대상이 아니다.
  testability를 2점으로 산정하고 "표시값과 그리기를 가르는" 전략으로 그 영역을
  얇게 유지했다. AC 28건 중 24건이 로직 테스트로 덮이고, 나머지는 배선이다 (design)
- [모음집이 있는 상태 미확인] 시뮬레이터에 탭을 넣을 수단이 없어 빈 상태만
  눈으로 봤다. 카드 렌더·상세·시트·재배치는 **사람이 한 번 만져 봐야 한다**
  (phase-complete)
- [캐러셀 재배치 미구현] v4 §4는 캐러셀에서 길게 눌러 끄는 것을 말하지만, 가로
  스크롤 드래그 재정렬은 SwiftUI 기본 도구로 만들 수 없다. `List.onMove`가
  접근성·햅틱까지 주는 「전체 보기」에 먼저 붙였다. **UX가 명세와 다르다** —
  Phase 6 후속 과제 (implement/T6)
- [생성 후 상세 자동 진입 미구현] v4 §4는 "생성 즉시 상세로 진입"인데 지금은
  캐러셀에 추가만 한다. 진입 직후 할 일이 캔버스 추가(Phase 3)라 지금 넣으면
  빈 화면으로 떨어진다 (implement/T6)
