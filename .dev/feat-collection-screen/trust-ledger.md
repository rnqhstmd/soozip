# Trust Ledger — Phase 6 모음집 화면

- 작성일: 2026-08-11
- 모드: 전체(all) / 표준 프로파일

## 보안 감사

이 변경은 화면 계층이다. 네트워크·자격증명·역직렬화 표면이 없고, 파일을 쓰는
경로도 없다. 실질적 위험은 **삭제**와 **표지 이미지 디코딩** 둘이다.

### [HIGH] 모음집 삭제가 캔버스와 사진까지 지운다 — 방어됨

- 0장만 즉시 삭제이고 1장부터는 개수를 명시해 확인을 받는다(`DeletionPrompt`)
- 문구를 값이 들고 있어 "N이 실제 개수인가"가 테스트로 측정된다
- cascade 자체는 Phase 1이 `deleteRule` 단독으로 검증했고, 화면이 부르는 경로가
  그 cascade에 닿는지를 이번에 다시 확인했다(AC-24)

### [MEDIUM] 신뢰할 수 없는 바이트를 이미지로 그린다 — 방어됨

`renderedPNG`는 CloudKit을 거쳐 다른 기기에서 올 수 있고, 손상된 채 도착할 수 있다.
디코딩 실패를 그대로 두면 빈 화면이 나온다.

- 프레젠터가 `canDecodeImage`로 **미리 걸러** `.image`에는 디코딩 가능이 확인된
  데이터만 담는다(BR-3, AC-6)
- 판정을 주입받으므로 실패 경로가 테스트로 측정된다
- `UIImage(data:)`는 파싱 실패 시 `nil`을 낼 뿐이고 이 계층은 그 결과만 쓴다

### [정보] 상세 화면의 `try?` 두 곳 — 의도적

초안 배너 조회와 삭제 실행이 실패를 삼킨다. 배너는 "없다고 보는" 쪽이 안전하고
(없는 초안을 있다고 하면 사용자가 작업물이 사라졌다고 읽는다), 삭제 실패는
목록이 그대로 남아 사용자가 재시도할 수 있다. 로깅 기반이 없어 기록할 곳도 없다 —
Phase 9에서 재검토.

**실측이 결함 1건을 잡았다**: 고스트 힌트를 `.overlay(alignment: .center)`로 띄워
화면 정중앙에 놓였고, `[+]` 카드와 멀찍이 떨어져 무엇을 가리키는 힌트인지 읽히지
않았다. 캐러셀 바로 아래 흐름으로 옮겼다.

### [문서 위험] AC 번호가 두 PRD 사이에서 충돌한다

AC 번호는 PRD마다 1부터 매겨지는데, `LibraryRepositoryTests.swift` 한 파일에
Phase 1과 Phase 6의 섹션이 함께 있다. 지금 `AC-14`가 두 뜻이다:

| 파일 위치 | 뜻 | 출처 |
|---|---|---|
| 상단 | 생성 순서가 정렬 순서다 | Phase 1 PRD |
| 하단 | 전체 보기는 `[+]`를 포함하지 않는다 | Phase 6 PRD |

`AC-11`·`AC-12`·`AC-13`·`AC-15`~`AC-18`도 같은 상태다. **테스트가 어느 PRD의
어느 조건을 재는지 읽는 사람이 알 수 없다.** 지금은 커밋 메시지로 추적되지만
`.dev/`가 정리되면 단서가 사라진다.

대응은 다음 Phase에서 섹션 머리에 출처를 붙이는 것(`P1 AC-14` / `P6 AC-14`)이
싸다. 이번에 안 고친 이유는 두 PRD의 전 섹션을 건드리는 변경이라 리뷰 diff를
불려 실제 코드 변경을 묻기 때문이다.

## 코드 리뷰 반영 (/code-review high)

지적 8건 전부 유효했고 오탐이 없었다. 8건 모두 수정했다.

### [CRITICAL] 릴리스 빌드가 컴파일되지 않았다

`@ToolbarContentBuilder` 본문을 `#if DEBUG`로만 채웠는데, 릴리스에서는 본문이 비고
`ToolbarContentBuilder`에는 인자 없는 `buildBlock()`이 없다. **Debug 빌드도 테스트
237개도 전부 초록이었다.**

가장 아픈 부분은 이걸 놓친 경위다. AC-28("릴리스에 스파이크 미포함")을 "자동 검증
불가"로 기록해 놓고, **정작 릴리스 빌드를 한 번도 돌려보지 않았다.** 검증 불가라고
적은 것이 확인을 안 할 근거가 되어 버렸다.

- 수정: `#if DEBUG`를 `spikeMenuToolbar()` 안으로 옮겨 릴리스에서는 `self`를 반환
- **재발 방지: `scripts/test.sh`에 릴리스 빌드를 넣었다.** 이 결함이 통과했다는
  것은 검증 스크립트에 구멍이 있었다는 뜻이고, 그 구멍이 진짜 문제다

### [MEDIUM] 삭제 다이얼로그에서 빠져나올 수 없었다

`isPresented: .constant(deleting != nil)`가 SwiftUI의 닫기 write-back(`false`)을
삼켜, 두 버튼을 거치지 않는 닫기 경로(VoiceOver 이스케이프·하드웨어 Esc·시스템
해제)에서 `deleting`이 남고 다이얼로그가 다시 떴다. 제대로 된 `Binding`으로 교체.

### [MEDIUM] 고스트 힌트가 되살아났다 — 정책은 맞고 배선이 빠졌다

`ghostHintDismissed`를 힌트 탭에서만 기록해서, 힌트를 무시하고 `[+]`를 누른
사용자는 플래그가 `false`로 남았다. 나중에 모음집을 전부 지우면 힌트가 다시 뜬다 —
`GhostHintPolicy` 주석이 금지한 바로 그 동작이다. **테스트는 정책만 재고 배선은
안 재기 때문에 초록이었다.** 생성 시에도 기록하도록 수정.

### [MEDIUM] 카드마다 전량 fetch가 돌았다

`card(for:)` → `canvases(in:)` → `Canvas` 전량 fetch. 모음집 20개면 본문 한 번
평가에 전량 조회가 20번 일어난다. 앱 첫 화면이라 그대로 체감된다.
`canvasesByCollection()`으로 한 번 읽고 소속별로 나눠 쓰도록 수정.

### [LOW] 4건

- 상세의 초안 배너 판정이 메인 액터에서 디스크를 훑었다 → `Task.detached`로 이동
- `renameCollection`이 저장 실패 후 새 이름을 남겼다 → 롤백 추가
- 재배치·삭제 실패를 삼켰다 → 실패 알림 추가
- 공백만 있는 이름이 통과했다("   "가 3자) → 시트에서 트리밍
  (설계가 "트리밍은 Phase 6 UI 몫"으로 미뤄 뒀고 여기가 그 자리였다)

## 위험 수용

- [AC-28 자동 검증 불가 — 부분 해소] `#if DEBUG` 자체는 여전히 테스트로 못 잰다.
  다만 **릴리스 빌드가 `scripts/test.sh`에 들어가** "릴리스가 컴파일되는가"는
  이제 기계가 검사한다. 남은 것은 "스파이크가 릴리스에 실리지 않는가"뿐이고
  이건 코드 리뷰 몫이다 (code-review 후속)
- [기존 기록] AC-28 자동 검증 불가 "릴리스 빌드에 스파이크 진입 경로 없음"은 `#if DEBUG`
  컴파일 타임 분기인데 테스트 자체가 DEBUG에서 돈다. `SpikeMenu.swift` 파일
  전체를 `#if DEBUG`로 감싸는 것으로 대응하고, 확인은 코드 리뷰에 맡긴다 (design)
- [뷰 계층 테스트 미적용] SwiftUI 뷰·앱 루트 배선은 자동 검증 대상이 아니다.
  testability를 2점으로 산정하고 "표시값과 그리기를 가르는" 전략으로 그 영역을
  얇게 유지했다. AC 28건 중 24건이 로직 테스트로 덮이고, 나머지는 배선이다 (design)
- [모음집이 있는 상태 미확인] 시뮬레이터에 탭을 넣을 수단이 없어 빈 상태만
  눈으로 봤다. 카드 렌더·상세·시트·재배치는 **사람이 한 번 만져 봐야 한다**
  (phase-complete)
- [캐러셀 재배치 미구현] v4 §4는 캐러셀에서 길게 눌러 끄는 것을 말하지만, 가로
  스크롤 드래그 재정렬은 SwiftUI 기본 도구로 만들 수 없다. `List.onMove`가
  접근성·햅틱까지 주는 「전체 보기」에 먼저 붙였다. **UX가 명세와 다르다** —
  Phase 6 후속 과제 (implement/T6)
- [생성 후 상세 자동 진입 미구현] v4 §4는 "생성 즉시 상세로 진입"인데 지금은
  캐러셀에 추가만 한다. 진입 직후 할 일이 캔버스 추가(Phase 3)라 지금 넣으면
  빈 화면으로 떨어진다 (implement/T6)
