# EDITOR-8 — 회전 (15° 스냅) · PR 배경 자료

## 배경

캔버스 스마트 가이드 4종 중 정렬·균등 간격·크기 일치는 이미 있고 **회전만 비어 있었다.** `SnapKind`가 3종뿐이고 `SnapCandidate`가 `axis`(수평/수직) + `value` 구조라 **회전각을 담을 자리가 구조적으로 없다** — 회전에는 축도, 그을 가이드 선도 없다(v4가 지정한 표현은 각도 배지다).

**`EDITOR-6`이 이미 이 그리드에 의존하고 있었다.** `HandlePlacement`의 코너 밀기 실측 문서가 *"15° 눈금 24개 중 안쪽으로 미는 회전: 정사각 200×200 13개 · 세로긴 100×300 12개 · 가로긴 300×100 12개. `EDITOR-8`이 15° 스냅이라 전부 도달 가능하다"*로 적혀 있어, 다른 간격을 채택하면 그 실측이 통째로 무효가 될 참이었다.

그리고 **정렬 가이드에 이미 버그가 있었다.** 후보 자격 판정이 `abs(rotation) < 0.0001`이라 **한 바퀴 돈 레이어가 회전체로 오판**됐다 — 시각적으로는 축에 정렬돼 있는데 가이드가 안 걸린다.

## 요구사항

- **FR-1·2** 15° 그리드에서 **3° 미만**이면 흡착. **정확히 3°는 미흡착**(엄격 부등호)
- **FR-3** `[0°, 360°)` 정규화
- **FR-4** 흡착은 **정규화 이전 원본 기준** — 누적 바퀴 수 보존(`373° → 375°`, `359° → 360°`)
- **FR-5** 흡착 구간에 **방금 들어온 순간에만** 발화(enter 이벤트)
- **FR-6** 축 정렬 판정을 **가장 가까운 360° 배수까지의 거리**로 (기존 버그 수정)
- **FR-7** 비유한 입력은 크래시 없이 후퇴하며 **유한값으로 조용히 바뀌지 않는다**
- **FR-8** **유한 입력은 비유한 결과를 내지 않는다**
- **FR-9** *(Should)* 그리드 간격·흡착 임계를 공개 상수 단일 출처로

## 이 단위에서 밝혀진 것

**판정 본체를 도(degree) 공간에 둬야 한다 — 라디안이면 규칙이 실제로 깨진다.** 실측: 라디안에서 거리와 임계를 재면 `|12° − 15°| = 0.05235987755982985`이고 임계 3°는 `0.05235987755982989`라 **거리가 임계보다 작아 흡착된다.** 도 공간은 `3.0 < 3.0`이 거짓이라 미흡착이다. 부수적으로 `3 * (π/180)`과 `π/60`이 **1 ulp 다르다**는 것도 확인했다 — "라디안 상수는 어떻게 써도 같다"는 일반적으로 거짓이다.

**축 정렬 수정이 자기 유발 회귀를 만들 뻔했다.** `[0, 2π)`로 정규화한 뒤 0 근접 비교로 바꾸면 `rotation = -0.00005`가 `6.28313…`이 되어 **오늘 통과하던 입력이 깨진다.** "가장 가까운 2π 배수까지의 거리"로 재야 한다.

**유한 라디안 입력이 NaN을 낳는 경로가 있었다.** `degrees(fromRadians: 1e308)`이 `inf`가 되고(rad→deg 오버플로 문턱 `|r| ≥ 3.1375664143845866e306`), `fmod(inf, 360)`이 **NaN**이다. NaN이 레이어 `rotation`에 앉으면 **`JSONEncoder`가 던져 문서 저장 자체가 실패한다.** 라디안 정규화를 도 정규화 합성으로 만들지 않고 **접기 본체를 `period`로 매개변수화**해 그 경로를 프로덕션에서 제거했다.

**변이를 실제로 적용해 각 테스트가 무엇을 죽이는지 측정했고, 그 과정에서 설계 근거 여러 건이 틀렸음을 확인했다.** 예: 설계는 "AC-4·7·8이 바퀴 수 보존의 증인"이라 했지만 실측하니 **`AC-8`(359→360)은 어떤 정규화 변이도 죽이지 못한다**(`359 < 360`이라 두 정규화가 모두 항등이다). 실제 유일 증인은 `AC-7`이다. 이런 정정을 doc에 반영해, 다음 단위가 잘못된 논증을 물려받지 않게 했다.

## 리뷰에서 나온 것

**Critical 0 · 실행 코드 결함 0건.** 두 차례 리뷰에서 나온 Important 12건은 **전부 주석-코드 불일치**였다. 이 저장소는 주석이 설계 원장이라 **다음 단위가 잘못된 서술에서 설계를 재구성하는 것**이 실제 비용이다.

1회차 정정에서 실행 코드 1줄을 바꿨는데(`isAxisAligned`가 자체 접기 대신 `RotationSnap.normalized(radians:)` 재사용 — 실측으로 완전 동등 확인), **그 교체가 변이 킬셋 구조를 바꿔 주석 4곳을 낡게 만들었다.** 2회차가 그것을 잡았다. 근본 원인은 **같은 실측 사실이 프로덕션 doc과 테스트 주석 두 곳에 적혀 있던 것**이라, 축 정렬 축에 "프로덕션이 원장 / 테스트는 포인터" 패턴을 적용해 이중 기술을 제거했다.

**오케스트레이터 자기 정정 1건**: 파이프라인 내내 "이 저장소는 `Double ==` 선례가 0건"이라는 전제를 에이전트들에게 전달했고 그것이 프로덕션 doc에 박혔는데, **사실이 아니었다**(`fitScale == 0`·`value == 250` 등 실재). 정확한 진술로 고쳤다.
