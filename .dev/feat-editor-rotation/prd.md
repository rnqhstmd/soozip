# EDITOR-8 — 회전 (15° 스냅)

## 배경

캔버스 스마트 가이드 중 정렬·균등 간격·크기 일치는 이미 구현되어 있고, **회전만 비어 있다**. `SnapKind`가 `alignment`/`equalSpacing`/`sizeMatch` 3종뿐이고, `SnapCandidate`가 `axis`(수평/수직) + `value` 구조라 **회전각을 담을 자리가 구조적으로 없다**. 지금 레이어를 돌리면 15° 단위로도 임의 각도로도 걸리는 것이 없어, 수평·수직·45°를 맞추는 일이 전적으로 눈대중이다.

`LayerFrame.rotation`은 라디안이고 **생성자에 값 범위 제약이 전혀 없다** — 음수도, 여러 바퀴 넘긴 값도 그대로 들어온다.

**`EDITOR-6`(핸들 겹침 방지)이 이미 이 그리드에 의존하고 있다.** `HandlePlacement.swift:230`의 실측 문서가 *"15° 눈금 24개 중 안쪽으로 미는 회전: 정사각 200×200 **13개**(90°~270° 전 구간) · 세로긴 100×300 **12개**(75°~240°) · 가로긴 300×100 **12개**(120°~285°). `EDITOR-8`이 15° 스냅이라 전부 도달 가능하다"*로 적혀 있다. **이번 단위가 다른 간격을 채택하면 그 실측 문장이 통째로 무효가 된다.**

정렬·간격 가이드의 후보 자격 판정(`isAxisAligned`)은 지금 `abs(rotation) < 0.0001`만 본다. **정규화를 순진하게 들여오면 오늘 통과하던 입력이 깨진다** — `rotation = -0.00005`는 현재 축 정렬(참)인데 `[0, 2π)`로 접으면 `6.28313…`이 되어 거짓이 된다. 이 단위가 스스로 만들 수 있는 회귀다.

배지 렌더·햅틱 재생·제스처 배선은 이 단위에 없다. "이 각도가 스냅 대상인가, 스냅 구간에 방금 들어왔는가"를 계산하는 **순수 판정**만 다룬다.

## 범위

**포함** — 15° 그리드 스냅 판정 · `[0°, 360°)` 정규화 · 회전 바퀴 수 보존 · 스냅 구간 진입(enter) 판정 · 기존 축 정렬 판정의 회귀 방지 · **비유한 입력/결과 방어**

**제외** — 각도 배지 렌더링 · 스냅 햅틱(`selection`) 재생 · 손가락 제스처 배선 (전부 `EDITOR-11`)

이 로직이 놓이는 `SoozipGeometry`는 **Foundation 전용**이며 `LayerKind`·`CanvasAspect`를 볼 수 없다. 따라서 판정은 애초에 레이어 타입별로 갈라질 수 없고, 5종이 공유하는 단일 회전값(`Double`)만 받는다.

## 요구사항

- **[Must] FR-1** 회전 각도가 15° 그리드(0°·15°·30°···345°, 24개 지점) 중 어느 값으로부터 3° **미만** 떨어져 있으면, 그 그리드 값으로 흡착한 각도를 반환한다.
- **[Must] FR-2** 어느 그리드 값까지의 거리도 3° 미만이 아니면(**정확히 3°인 경우 포함**), 흡착하지 않고 입력 각도를 그대로 반환한다.
- **[Must] FR-3** 임의의 각도(음수·360° 이상 포함)를 `[0°, 360°)` 범위의 항상 양수인 값으로 접는 정규화 기능을 제공한다.
- **[Must] FR-4** 흡착 판정은 **정규화 이전의 원본 각도**(누적 회전 바퀴 수 포함)를 기준으로 이루어져, 흡착 후에도 바퀴 수가 보존된다.
- **[Must] FR-5** 회전 각도가 스냅 구간 밖에서 안으로 **방금 들어온 순간에만** 참을 반환하는 "흡착 진입" 판정을 제공한다. 이미 구간 안에 머무는 동안에는 거짓을 반환한다(재발화 없음).
- **[Must] FR-6** 정렬 가이드가 쓰는 기존 축 정렬 판정은, 각도를 정규화한 뒤 그 결과가 0에 가까운지 보는 방식이 **아니라**, **가장 가까운 360° 배수까지의 거리**로 판정한다.
- **[Must] FR-7** 회전각 입력이 비유한(NaN·±Infinity)이면 흡착·정규화·진입 판정 모두 크래시 없이 후퇴하며, **비유한 입력이 유한값으로 조용히 바뀌지 않는다**.
- **[Must] FR-8** **유한 입력은 비유한 결과를 내지 않는다.** 극단적으로 큰 유한 각도에서도 반환값이 유한하다.
- **[Should] FR-9** 그리드 간격(15°)과 흡착 임계(3°)는 **프로덕션의 공개 상수 단일 출처**로 노출되어, 배선 단위가 자기 리터럴을 박지 않고 이 값을 읽는다.

## 비즈니스 규칙

- **[Must] BR-1** 스냅 그리드는 0°부터 345°까지 15° 간격, 24개 지점이다.
- **[Must] BR-2** 흡착 임계는 "그리드 값까지 거리 3° **미만**"이다 — 엄격 부등호. **정확히 3° 떨어진 값은 이전 상태(미흡착)를 유지한다.** 이 저장소의 `edgeHideThreshold`(88pt, `>= 88`이면 변 있음)·`cornerPushThreshold`(56pt, `< 56`이면 밀기)가 세운 "경계는 이전 상태" 관례를 따른다. `flipThreshold`(40pt, `<= 40`)만 반대인데 그것은 `HandlePlacement.swift:86`이 예외로 명시 문서화한 자리다.
- **[Must] BR-3** 정규화 결과는 항상 `[0°, 360°)` 범위의 양수다.
- **[Must] BR-4** *(설계 제약 — 수용 기준 없음)* 스냅·정규화·축 정렬 판정에 레이어 타입별 분기를 두지 않는다. `SoozipGeometry`가 `LayerKind`를 볼 수 없고 `Layer.transform` 접근자에 타입 분기가 없어 **구조적으로 항상 성립하므로 검증 대상이 아니다** — 설계 의도만 명시한다.
- **[Must] BR-5** 축 정렬 허용오차(0.0001 rad)와 회전 스냅 임계(3°)는 **목적이 다른 별개 규칙이며 하나로 통합하지 않는다**. 전자는 "정렬·간격 가이드 후보 자격", 후자는 "회전 핸들 그리드 흡착"이다.
- **[Must] BR-6** 그리드 간격과 흡착 임계는 외부 조회 가능한 공개 상수여야 한다.

## 수용 기준

**AC-1: 그리드에 가까운 각도가 흡착된다**
- Given: 회전 각도가 14°(그리드 값 15°까지 거리 1°)이다
- When: 흡착 판정을 실행한다
- Then: 흡착 여부가 참이고 결과 각도가 15°다 → [FR-1]

**AC-2: 임계 바로 안쪽에서도 흡착된다**
- Given: 회전 각도가 12.1°(그리드 값 15°까지 거리 2.9°)이다
- When: 흡착 판정을 실행한다
- Then: 흡착 여부가 참이고 결과 각도가 15°다 → [FR-1 / BR-2]

**AC-3: 경계값 정확히 3°는 흡착되지 않는다**
- Given: 회전 각도가 12°(그리드 값 15°까지 거리 정확히 3°)이다
- When: 흡착 판정을 실행한다
- Then: 흡착 여부가 거짓이고 결과 각도가 12° 그대로다 → [FR-2 / BR-2]

**AC-4: 음수 각도도 흡착된다**
- Given: 회전 각도가 -13°(가장 가까운 그리드 값 -15°까지 거리 2°, 0°까지는 13°)이다
- When: 흡착 판정을 실행한다
- Then: 흡착 여부가 참이고 결과 각도가 -15°다 → [FR-1]

**AC-5: 두 그리드 사이 한가운데는 흡착되지 않는다**
- Given: 회전 각도가 7°(0°까지 7°, 15°까지 8° — 양쪽 모두 3° 초과)이다
- When: 흡착 판정을 실행한다
- Then: 흡착 여부가 거짓이고 결과 각도가 7° 그대로다 → [FR-2]

**AC-6: 이미 그리드 위인 각도는 움직이지 않는다**
- Given: 회전 각도가 30°(그리드 값과 정확히 일치, 거리 0)이다
- When: 흡착 판정을 실행한다
- Then: 결과 각도가 30° 그대로다 → [FR-1]

**AC-7: 누적 바퀴 수가 보존된다**
- Given: 회전 각도가 373°(한 바퀴 + 13°, 그리드 값 375°까지 거리 2°)이다
- When: 흡착 판정을 실행한다
- Then: 결과 각도가 375°다 — 정규화된 13°나 15°로 접히지 않는다 → [FR-4]

**AC-8: 한 바퀴 경계에서도 접지 않는다**
- Given: 회전 각도가 359°(그리드 값 360°까지 거리 1°)이다
- When: 흡착 판정을 실행한다
- Then: 결과 각도가 360°다 — 0°로 접지 않는다 → [FR-4]

**AC-9: 음수 각도가 양수로 정규화된다**
- Given: 회전 각도가 -30°이다
- When: 정규화를 실행한다
- Then: 결과가 330°다 → [FR-3 / BR-3]

**AC-10: 여러 바퀴 각도가 정규화된다**
- Given: 회전 각도가 725°(두 바퀴 + 5°)이다
- When: 정규화를 실행한다
- Then: 결과가 5°다 → [FR-3 / BR-3]

**AC-11: 미세 음수 회전이 축 정렬로 유지된다 (자기 유발 회귀 방지)**
- Given: 회전 각도가 -0.00005 rad(축 정렬 허용오차 0.0001 rad 이내의 미세 음수)인 레이어가 있다
- When: 정렬·간격 가이드의 축 정렬 판정을 실행한다
- Then: 축 정렬 판정이 참이고 이 레이어가 스냅 후보에 포함된다 — `[0, 2π)` 정규화 후 0 근접 비교로 바꾸면 `6.28313…`이 되어 거짓으로 뒤집히는데, 그 회귀가 일어나지 않는다 → [FR-6]

**AC-12: 한 바퀴 돈 레이어도 축 정렬로 인식된다 (기존 버그 수정)**
- Given: 회전 각도가 2π rad(정확히 한 바퀴)인 레이어가 있다
- When: 정렬·간격 가이드의 축 정렬 판정을 실행한다
- Then: 축 정렬 판정이 참이다 — 기존 `abs(rotation) < 0.0001`은 이 입력에 거짓을 반환해 후보에서 잘못 제외했다 → [FR-6]

**AC-13: 흡착 구간에 진입하는 순간에만 참이다**
- Given: 직전 각도가 20°(모든 그리드로부터 3° 초과)이고 현재 각도가 17°(15°까지 2°)이다
- When: 흡착 진입 판정을 실행한다
- Then: 결과가 참이다 → [FR-5]

**AC-14: 같은 구간에 머무는 동안 재발화하지 않는다**
- Given: 직전 각도가 17°(흡착 중, 목표 15°)이고 현재 각도가 16°(여전히 흡착 중, 목표 15°)이다
- When: 흡착 진입 판정을 실행한다
- Then: 결과가 거짓이다 → [FR-5]

**AC-15: 비유한 입력이 유한값으로 조용히 바뀌지 않는다**
- Given: 회전 각도가 `Double.nan`이다
- When: 흡착 판정과 정규화를 각각 실행한다
- Then: 크래시 없이 반환되고, 흡착 여부가 거짓이며, 결과 각도가 여전히 비유한이다 — 임의의 유한값(예: 0)으로 대체되지 않는다 → [FR-7]

**AC-16: 무한대 입력도 안전하게 후퇴한다**
- Given: 회전 각도가 `Double.infinity`이다
- When: 흡착 판정을 실행한다
- Then: 크래시 없이 반환되고 흡착 여부가 거짓이다 → [FR-7]

**AC-17: 극단적으로 큰 유한 각도에서도 결과가 유한하다**
- Given: 회전 각도가 `1e308`(유한하지만 15°(≈0.2618 rad)로 나누면 `3.82e308 > Double.greatestFiniteMagnitude`라 무한대가 되는 크기)이다
- When: 흡착 판정과 정규화를 각각 실행한다
- Then: 두 결과 모두 유한하다 — 유한 입력이 비유한 결과를 낳지 않는다 → [FR-8]

**AC-18: 그리드 간격과 흡착 임계가 프로덕션 공개 상수로 고정되어 있다**
- Given: 프로덕션이 노출한 그리드 간격·흡착 임계 접근자가 있다
- When: 그 값을 읽는다
- Then: 그리드 간격이 정확히 15°, 흡착 임계가 정확히 3°다 — 값을 바꾸는 변이가 이 단언에서 죽는다 → [FR-9 / BR-6]

## 확정 이력

- **1차 초안 → 확정본 반영**: 경계 제외(정확히 3°는 미흡착) · 정규화 범위 `[0°, 360°)` · 바퀴 수 보존 · 공허한 AC 2건 처리(음수 각도는 `-13°`로 수치 교체, "5종 동일 적용"은 삭제하고 BR-4 설계 제약으로 격하).
- **오케스트레이터 정정 2건**: ① `v4:55`("회전 시 레이어 좌표는 변하지 않는다")는 **기기 회전** 이야기라 근거에서 제거. ② "저장소가 대체로 경계 포함(`<=`) 관례"라는 진술은 사실이 아님 — 3개 중 2개가 "경계는 이전 상태"이며 `HandlePlacement.swift:86`이 이 갈라짐을 명시 문서화하고 있다.
- **오케스트레이터 복원 1건**: 1차 초안에 있던 **비유한 방어(FR-5)와 NaN/Infinity AC 2건이 확정본에서 사유 없이 삭제**되어 `FR-7`·`AC-15`·`AC-16`으로 복원했다. 근거는 `EDITOR-7`의 결론 — 비유한 값이 public API 밖으로 나가면 `JSONEncoder`가 던져 **문서 저장 자체가 실패한다**. 더구나 이 단위의 정규화 결과가 그대로 `LayerTransform.rotation`에 앉으므로, **`EDITOR-7`이 찾지 못하고 이월한 "비유한 `rotation`의 라이브 도달 경로"를 이 단위가 만들 수 있다**.
- **오케스트레이터 신규 1건**: `FR-8`·`AC-17`. 유한 입력 `1e308`이 `15°(0.2617993877991494 rad)`로 나뉘면 `3.82e308 > Double.greatestFiniteMagnitude`가 되어 무한대로 넘치고, 다시 곱해도 무한대가 남는다. `EDITOR-7`의 극단 비율 오버플로와 같은 형태다.
