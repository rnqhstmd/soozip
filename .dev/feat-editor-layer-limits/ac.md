# EDITOR-3 — 타입별 상한

- 작성일: 2026-08-12
- 로드맵: `docs/plans/2026-08-11-00-tdd-roadmap-v1.md` (editor 도메인)
- 설계 SSOT: v4 §5.13(레이어 상한) · §5.12.1(복제도 상한에 포함)
- 브랜치: `feat/editor-layer-limits` (base `main`)
- 모드: 핵심(core) / 표준 프로파일

## 배경

v4 §5.13:

| 대상 | 상한 | 근거 |
|---|---|---|
| `photo` | **8** | PHPicker 상한과 동일. 2000px 한 장 디코딩이 약 16MB |
| `drawing` | **5** | PencilKit을 캔버스 크기 비트맵으로 굽는다 |
| `text` + `shape` + `stamp` **합** | **30** | 메모리보다 단일 선택 UI의 조작성 문제 |

> "상한 도달 시 **해당 도구를 비활성화**하고 '사진은 8장까지 넣을 수 있어요'
> 형태로 안내한다."

**병목은 익스포트가 아니라 디코딩된 비트맵**이라 상한을 전체 개수가 아니라
타입별로 건다.

### 이미 있는 것

`LayoutDocument.validate()`가 `LayoutViolation?`을 낸다. `CanvasPromoter`가
승격 1단계에서 이걸 쓴다(`CANVAS-1`).

**그런데 그건 사후 판정이다** — 이미 상한을 넘긴 문서를 걸러낼 뿐, 넘어가는 것을
막지 않는다. `LayerStore.insert`는 지금 **무제한**이다(`EDITOR-2` 원장의 위험 수용).

### 이 단위의 진짜 위험 — 분류가 두 벌로 갈라진다

타입 → 범주 매핑(`text`·`shape`·`stamp`가 **합산**된다)이 지금
`validate()` 안의 `switch`에만 있다. 스토어가 상한을 막으려고 같은 `switch`를
다시 쓰면 **두 벌이 되고, 한쪽만 바뀌면 조용히 어긋난다** — 삽입은 막히는데
저장은 통과하거나, 그 반대가 된다.

`EDITOR-1`의 `workArea`를 공개해 `EDITOR-9`가 다시 정의하지 못하게 한 것과
같은 자리다. **분류와 상한을 한 곳으로 끌어내고 양쪽이 그것을 쓴다.**

### 거부는 던진다

이 저장소의 규칙이다 — 실패는 **맥락을 들고 던진다**(`PromotionError`·
`RepositoryError`). 조용히 `nil`을 돌려주면 호출부가 무시할 수 있고, 그게 이
저장소에서 반복된 사고 유형이다.

정상 흐름에서는 도구 버튼이 이미 비활성이므로 던지는 일 자체가 드물다 —
**던진다는 것은 배선이 판정을 안 썼다는 신호**다.

## 요구사항

- FR-1: 타입 → 범주 분류와 범주별 상한을 **한 곳**에 둔다. `validate()`와
  스토어가 그것을 쓴다.
- FR-2: 상한에 도달한 범주의 레이어는 **삽입을 거부한다.** 무엇이 몇 개
  한도인지 호출부가 알 수 있어야 한다.
- FR-3: 거부는 스토어를 **바꾸지 않는다.**
- FR-4: 도구 비활성 판정을 제공한다 — 범주별로 더 넣을 수 있는지, 몇 개 남았는지.
- FR-5: 상한을 이미 넘긴 문서를 불러와도 **잘라내지 않는다.**

## 수용 기준

### 삽입 차단 (FR-2·3)

- **AC-1**: Given 사진 8장이 있을 때, When 사진을 더 넣으면, Then
  `limitReached(category: .photo, limit: 8)`로 거부된다.
- **AC-2**: Given 같은 상황에서, When 거부되면, Then **스토어가 그대로다**
  (개수·순서·식별자 전부).
- **AC-3**: Given 펜 5개일 때, When 펜을 더 넣으면, Then `.drawing` 상한 5로
  거부된다.
- **AC-4**: Given 장식 30개일 때, When 텍스트·도형·도장 중 무엇을 넣어도,
  Then `.decor` 상한 30으로 거부된다.

### 합산과 독립 (FR-1)

- **AC-5**: Given 텍스트 10 · 도형 10 · 도장 10일 때, When 장식을 더 넣으면,
  Then 거부된다 — **세 타입이 합산된다.** 각각 30이 아니다.
- **AC-6**: Given 사진 8장으로 꽉 찼을 때, When **텍스트**를 넣으면, Then
  **들어간다** — 범주가 다르면 독립이다.

### 도구 비활성 판정 (FR-4)

- **AC-7**: Given 사진 7장일 때, When 판정을 물으면, Then 사진은 넣을 수 있고
  **1개 남았다**고 답한다.
- **AC-8**: Given 사진 8장일 때, When 판정을 물으면, Then 사진은 **넣을 수 없고
  0개 남았다**고 답한다.
- **AC-9**: Given 사진 8장에서 하나를 지웠을 때, When 사진을 넣으면, Then
  **들어간다** — 삭제가 자리를 되돌린다.

### 손상·초과 문서 (FR-5)

- **AC-10**: Given 사진 12장짜리 문서를 불러올 때, When 스토어를 만들면, Then
  **12장이 그대로 있다** — 잘라내지 않는다. 사용자의 작업물을 임의로 버리지 않는다.
- **AC-11**: Given 같은 상황에서, When 판정을 물으면, Then 넣을 수 없고
  **남은 개수는 0**이다 (음수가 아니다).

### 단일 출처 (FR-1)

- **AC-12**: Given 각 범주를 상한까지 정확히 채운 스토어일 때, When 그 레이어로
  문서를 만들어 `validate()`하면, Then **위반이 없다.** 스토어의 상한 판정과
  문서의 사후 판정이 **같은 경계**를 쓴다는 뜻이다.

## 범위 밖

- **안내 문구**("사진은 8장까지 넣을 수 있어요") — 배선(`EDITOR-11`).
  에러가 범주와 상한을 들고 있으므로 호출부가 만든다
- **도구 버튼 비활성 렌더** — 배선(`EDITOR-11`). 판정만 제공한다
- **복제 시 상한 검사** — `TOOL-3`. 복제도 `insert`를 타므로 자동으로 걸린다
- **선택 상태** — `EDITOR-4`
