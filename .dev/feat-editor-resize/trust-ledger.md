## Trust Ledger — EDITOR-7 (리사이즈)

### 통합 감사 (review) — security-auditor

> 아래 모든 항목을 **오케스트레이터가 `swiftc`로 독립 재현**했다. 재현 결과를 각 항목에 적었다.

- **[RISK/HIGH] 음수 캔버스가 `maxLongSide < 0`을 만들면 결과가 음수 크기가 되고, 두 가드가 모두 통과시킨다.**
  - 근거(**오케스트레이터 재현 완료**): `Size2(width: -1080, height: -1350)` → `longSide = max(-1080,-1350) = -1080` → `maxLongSide = -4320`. 정상 클램프 입력 `(300,150)`에서 `longSide(300) > -4320`이 참이라 `k = -14.4`가 곱해져 **`(-4320, -2160)`**. 이어지는 하한 블록은 `shortSide > 0`이 거짓이라 스킵. **두 값 모두 `isFinite == true`이므로 진입 가드도 결과 유한성 가드도 잡지 못한다.**
  - **설계서에 없다.** 「보장하지 않는다」 4행은 `maxLongSide ≤ 0`을 적었지만 분석은 **`== 0`(→ `(0,0)`)만** 했다. 음수는 `(0,0)`이 아니라 **음수 크기**를 내며 더 나쁘다.
  - 도달 경로: `resizeLimits(canvas:)`가 `public`이고 `Size2`가 부호를 검증하지 않는다(`Vec2.swift:20-33`). **프로덕션 호출부는 0건**(독립 grep 재확인)이라 오늘 도달하지 않는다.
  - **이월**: `EDITOR-11` 배선 시 `canvas.width > 0 && canvas.height > 0` 가드 필수. 또는 `clamped`에 `maxLongSide > 0` 조건 추가.

- **[POLICY/HIGH] `maxLongSide == 0`이면 BR-1이 완전히 무력화된다.**
  - 근거(**재현 완료**): `resizeLimits(canvas: .zero)` → `(40, 0)` → 상한 블록 `k = 0` → 모든 입력이 `(0,0)` → 하한 블록은 `shortSide > 0`이 거짓이라 스킵 → `(0,0)`은 유한하므로 결과 가드도 통과. **BR-1이 막으려던 "레이어가 점이 되어 다시 못 잡는" 상태가 그대로 재현된다.**
  - 전제조건은 **오늘 이미 성립한다** — `LayoutDocument.init(from:)`(`:166-168`)이 캔버스 w/h를 `decode(Double.self)`로만 읽고 0·음수·범위 검증이 전혀 없다. 다만 그 값이 `resizeLimits`로 이어지는 **배선이 아직 없다.**
  - 설계서 4행이 이 항목을 정확히 이월했다. **이월 유지** — `EDITOR-9`/`EDITOR-11`.

- **[GAP/HIGH] `resized(draggingEdge:)`에 FR-5 방어가 전혀 없고, `NaN`이 실제로 결과로 샌다.**
  - 근거(**오케스트레이터 확인**): 해당 함수 본문에 `guard`·`isFinite`가 **0건**(awk 추출로 확인). 감사자의 수치 추적: `.right` 변을 `(.nan, 300)`으로 끌면 `toLocal`에서 두 성분이 모두 `NaN`(`NaN × -0.0 = NaN`) → `newW = NaN`, `newH = 100` → 클램프 두 블록 모두 비교가 거짓이라 스킵 → `deltaW = NaN` → `toWorld`에서 `NaN × 0 = NaN`이라 **`center`가 양 성분 모두 `NaN`**. 최종 `center = (NaN, NaN)`, `size = (NaN, 100)`.
  - PRD 범위 밖 표 B·설계서 9행이 "변 드래그 FR-5 방어 없음"을 이미 이월했다. **판단은 타당하다**(호출부 0건). 다만 **어떤 값이 새는지 수치가 설계서에 없었다** — 위 값을 `EDITOR-11` 인계에 포함한다.
  - **이월**: `EDITOR-11` 배선 시 코너 경로와 동형의 진입·결과 가드 필수.

- **[GAP/MEDIUM] 주석의 정밀 임계값 `2.2249e-307`이 오기다.**
  - **오케스트레이터 실측**: `40 / Double.greatestFiniteMagnitude = 2.2250738585072018e-307`. 문서값과 4번째 유효숫자에서 어긋난다. (상한 쪽 `4.494e306`은 실측 `4.4942328371557894e306`과 **일치**.)
  - 등장 위치: `ResizeAnchor.swift:152`·`:240`, `ResizeAnchorTests.swift:305`, `design.md` 5곳.
  - **이 값을 고정하는 테스트가 없다** — 틀려도 스위트가 초록이다. 이 저장소가 반복 경계해 온 "같은 규칙이 두 곳에 적혀 갈라진다"의 변형.
  - **처리: 이 단위에서 정정한다**(동작 불변 — 주석만).

- **[ASSUMPTION/MEDIUM] 캔버스 긴 변이 10 미만이면 상한이 사실상 죽는다.**
  - 근거(**재현 완료**): 캔버스 `5×5` → `maxLongSide = 20 < minShortSide(40)`. 클램프 입력 `(300,150)` → 상한 `k = 20/300` → `(20,10)` → 하한 `k = 4` → **`(80, 40)`**. 긴 변이 상한을 **4배** 초과한 채 확정된다.
  - BR-1("하한이 상한을 이긴다")과 모순되지 않는다 — 오히려 정확히 그 정책의 결과다. 그러나 FR-2의 취지("캔버스보다 과도하게 크지 않게")는 그 캔버스에서 **항상·필연적으로** 깨진다.
  - 현재 두 프리셋(5400·7680)은 40을 압도하므로 오늘 문제 없다. `resizeLimits`는 `maxLongSide > minShortSide`를 검증하지 않는다.
  - **이월**: `EDITOR-9`/`EDITOR-11` — 캔버스 최소 크기 정책과 함께.

- **[GAP/MEDIUM] `LayerStore` transform 쓰기 경로가 4번째 연속 이월됐고, HIGH 3건이 전부 `EDITOR-11`에 몰렸다.**
  - PRD 범위 밖 표 C가 "5번째 이월은 허용하지 않는다"고 못 박았다 — 추적은 적절하다. 다만 이번 감사의 HIGH 3건(음수 캔버스·`maxLongSide ≤ 0`·변 드래그 무방비)이 전부 같은 단위로 향해 그 단위의 리뷰 부담이 커졌다.
  - **권고**: `EDITOR-11` 착수 전 계획 단계에서 이 원장의 이월 목록을 우선순위와 함께 한 번에 정리할 것.

### 검증했고 문제를 찾지 못한 것 (security-auditor + 오케스트레이터)

- **AC-4 `(0,0)` → `(80,40)` 복원** — 손 재계산이 설계서 §4 산술과 정확히 일치.
- **AC-6 하한 우선** — `(8000,40)` 두 드래그 수렴, 부동소수 오차로 `isClose` 필수임이 구조적으로 타당.
- **`(2,1)` / `(200898,100449)`** — 한계값 오염 시 값이 실측과 정확히 일치. 단 현재는 진입 가드가 그 경로를 먼저 후퇴시키므로 **반사실적 예시**이며 실제 반환값이 아니다 — 테스트가 원본 등가를 단언하는 것과 정합.
- **AC-2 유도값** — `1350×4 = 5400`, `1920×4 = 7680` 일치.
- **`clamped` 호출부가 정확히 2개** — 파일 전문 확인, 제3의 호출부 없음.
- **"고정점 유지" 대수 항등** — `nc` 소거 재전개 확인. 반례 시도(비유한 rotation, 극단 스케일)는 전부 결과 가드가 흡수. 오케스트레이터 무작위 300회 실측 최대 편차 1.205e-11.
- **프로덕션 호출부 0건** — 저장소 전체 독립 grep으로 재확인.
- **`shortSideFloor` 이름 분리의 변이 차단** — 오케스트레이터가 `swiftc`로 직접 재현 확인(이름이 같으면 매개변수 삭제 변이가 컴파일되고 결과가 동일).
