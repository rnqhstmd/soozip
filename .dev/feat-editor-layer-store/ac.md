# EDITOR-2 — 레이어 스토어

- 작성일: 2026-08-12
- 로드맵: `docs/plans/2026-08-11-00-tdd-roadmap-v1.md` (editor 도메인)
- 설계 SSOT: v4 §5.2(5종 공통 경로) · §5.11(z-order)
- 브랜치: `feat/editor-layer-store` (base `main`)
- 모드: 핵심(core) / 표준 프로파일

## 배경

에디터가 편집 중에 들고 있는 레이어 목록이다. v4 §5.2: **"선택·이동·핀치·회전·
z-order·투명도는 5종이 완전히 동일한 경로를 탄다."** 그 경로의 바닥이 이 단위다.

`SoozipLayout`에 이미 있는 것 — 새로 만들지 않는다:

| 있는 것 | 어디 |
|---|---|
| `Layer` 5종 (`photo`·`text`·`shape`·`stamp`·`drawing`) + Codable | `Layer.swift` |
| `LayerTransform.z: Int` | `Layer.swift` |
| 타입별 상한 판정 `LayoutDocument.validate()` | `LayoutDocument.swift` (`EDITOR-3`) |

### 문제 1 — `Layer`에 식별자가 없다

선택도 재배치도 "어느 레이어"를 지목해야 하는데 `Layer`에는 id가 없다.
`PhotoLayer.assetId`는 **복제본끼리 공유한다**(v4 §5.12.1, BR-5). 사진 하나를
3번 복제하면 레이어 4개가 같은 `assetId`를 갖는다 — 키가 될 수 없다.

**식별자는 편집 세션 안에서만 산다.** `layoutJSON`(v4 §8)에 레이어 id 필드가
없고, 넣으면 저장 형식이 바뀐다. 재편집으로 문서를 열 때마다 새로 발급하면
되므로 영속화할 이유도 없다.

### 문제 2 — z를 저장하면 "촘촘함"을 계속 지켜야 한다

v4 §5.11: "재정렬 시 **0부터 다시 촘촘히 매긴다**(빈 번호가 쌓이면 상한에
부딪힌다)."

z를 필드로 들고 조작마다 재번호하면, **재번호를 한 곳에서라도 빠뜨리면 구멍이
생긴다.** 조작이 4종(맨 앞·앞·뒤·맨 뒤)에 삽입·삭제까지 6곳이다.

**대신 배열 순서를 진실로 삼고 z를 인덱스에서 파생시킨다.** 그러면 "0부터
촘촘히"가 **깨질 수 없는 성질**이 되고 재번호 코드 자체가 사라진다.

`EDITOR-1`에서 "배율·뷰포트에 독립인 것만 저장한다"고 정한 것과 같은 원리다 —
**불변식을 지키는 코드를 쓰는 대신, 불변식이 성립할 수밖에 없는 표현을 고른다.**

## 요구사항

- FR-1: 레이어 5종을 순서 있게 담고, 각 항목에 **세션 한정 식별자**를 준다.
- FR-2: z-order 4종(맨 앞으로·앞으로·뒤로·맨 뒤로)을 지원한다.
- FR-3: **어떤 조작 뒤에도** z는 0부터 촘촘하다.
- FR-4: 삽입·삭제를 지원한다. 새 레이어는 맨 앞에 온다.
- FR-5: 손상된 문서(z 중복·구멍)를 불러와도 순서가 결정적이다.

## 수용 기준

### 식별과 왕복

- **AC-1**: Given 레이어 3개로 스토어를 만들 때, When 각 항목의 식별자를 보면,
  Then **서로 다르다** — 같은 `assetId`를 공유하는 복제 사진이어도 그렇다.
- **AC-2**: Given 임의의 레이어 목록일 때, When 스토어에 넣었다가 `layers`로
  꺼내면, Then z를 제외한 내용과 **순서가 보존된다.**

### z-order 4종 (FR-2·3)

- **AC-3**: Given 맨 뒤 레이어를 지목했을 때, When **맨 앞으로**를 하면,
  Then 그것이 맨 앞이 되고 나머지 상대 순서는 그대로다.
- **AC-4**: Given 가운데 레이어를 지목했을 때, When **앞으로**를 하면,
  Then 바로 위 레이어와만 자리를 바꾼다.
- **AC-5**: Given 가운데 레이어를 지목했을 때, When **뒤로**를 하면,
  Then 바로 아래 레이어와만 자리를 바꾼다.
- **AC-6**: Given 맨 앞 레이어를 지목했을 때, When **맨 뒤로**를 하면,
  Then 그것이 맨 뒤가 된다.
- **AC-7**: Given 이미 맨 앞인 레이어일 때, When **맨 앞으로**·**앞으로**를 하면,
  Then **아무것도 바뀌지 않는다** (맨 뒤도 대칭).
- **AC-8**: Given 레이어 5개일 때, When z-order 4종·삽입·삭제를 **어떤 순서로
  섞어 실행해도**, Then z는 언제나 `0..<n`이고 중복이 없다.

### 삽입·삭제 (FR-4)

- **AC-9**: Given 레이어 2개일 때, When 새 레이어를 넣으면, Then **맨 앞**에
  오고 z가 2다.
- **AC-10**: Given 가운데 레이어를 지울 때, When 삭제하면, Then 나머지 z가
  **0부터 촘촘히 다시 매겨진다** — 구멍이 남지 않는다.
- **AC-11**: Given 없는 식별자를 지목할 때, When 어떤 조작을 하든, Then
  **아무 일도 일어나지 않는다** (크래시·오염 없음).

### 손상 문서 (FR-5)

- **AC-12**: Given z가 `[5, 5, 5]`로 **전부 같은** 문서를 불러올 때, When
  스토어를 만들면, Then **입력 배열 순서가 유지된다** — 정렬이 불안정하면 같은
  파일이 열 때마다 다른 순서로 보인다.
- **AC-13**: Given z가 `[10, 0, 7]`처럼 구멍투성이일 때, When 스토어를 만들면,
  Then z 오름차순으로 `0, 1, 2`가 된다.

## 범위 밖

- **타입별 상한** (`photo` 8 · `drawing` 5 · 나머지 30) — `EDITOR-3`.
  `LayoutDocument.validate()`에 이미 있고, 스토어는 상한을 강제하지 않는다
- **선택 상태·바운딩 박스** — `EDITOR-4`. 이 스토어는 무엇이 선택됐는지 모른다
- **복제** (`+40,+40`, `assetId` 공유) — `TOOL-3`
- **같은 지점 탭 시 최상단 선택** — `EDITOR-4`(히트 판정)
- 속성바 UI·`z-order` 버튼 배선 — `EDITOR-11`
